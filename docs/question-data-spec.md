# 問題データ仕様書（schemaVersion 1）

「計算ティーチャー！」の添削問題データの仕様です。問題を追加・修正するときは、この仕様に従ってください。
変更したら `npm test`（または `npm run validate`）を実行して確認します。

---

## 1. ファイル構成

```text
data/
├── manifest.json              読み込む単元ファイルの一覧（画面と検証スクリプトの両方が参照）
├── j1-positive-negative.json  中1 正負の数
├── j1-expressions.json        中1 文字式
└── j1-equations.json          中1 方程式
review/
└── manual-review.json         手動レビューの記録（tools/review-stamp.js で更新）
```

### manifest.json

```json
{
  "schemaVersion": 1,
  "files": [
    { "grade": 1, "unit": "positive-negative", "label": "正負の数", "file": "j1-positive-negative.json" }
  ]
}
```

単元を追加するときは、ここに1行足すだけで、ゲーム画面の単元一覧・プレビュー画面・検証の対象になります。

### 単元ファイル

```json
{
  "schemaVersion": 1,
  "grade": 1,
  "unit": "positive-negative",
  "questions": [ { 問題 }, { 問題 }, ... ]
}
```

ファイル内の `grade`・`unit` は manifest と一致させ、中の問題もすべて同じ単元にします。

## 2. 問題オブジェクト

### 必須項目

| 項目 | 型 | 内容 |
|---|---|---|
| `id` | string | `J{学年}-{単元記号}-{4桁}`。全ファイルで重複不可（例 `J1-EQ-0001`） |
| `grade` | 1 \| 2 \| 3 | 学年。単元の学年と一致させる |
| `unit` | string | 単元ID（3章） |
| `category` | string | 単元内のカテゴリ（3章の一覧から選ぶ） |
| `difficulty` | 1〜4 | 難易度（5章） |
| `question` | string (LaTeX) | 元の計算問題 |
| `answerLines` | string[] (LaTeX) | 生徒の答案。**1行目（index 0）は `question` と完全に同じ文字列** |
| `errorLine` | number \| null | 最初に誤った行の **0始まりの index**。全部正しいときは `null` |
| `errorType` | string \| null | 誤りの種類。全部正しいときは `null` |
| `explanation` | string | 誤りの理由、または全部正しい理由。`$...$` で数式を書ける |
| `correctSolution` | string[] (LaTeX) | 正しい計算過程。1行目は `question` と同じ |
| `hint` | string | トレーニングモード用のヒント。`$...$` で数式を書ける |

### 任意項目

| 項目 | 型 | 内容 |
|---|---|---|
| `instruction` | string | 問題の指示文。省略時は単元ごとの既定文（「次の計算をしなさい。」「次の方程式を解きなさい。」） |
| `substitution` | object | 式の値の問題で代入する値。例 `{ "a": "-2", "b": "3" }`（値は LaTeX の数）。自動検証で使う |
| `verification` | object | `{ "mode": "manual", "reason": "..." }` を指定すると、数式の自動検証を行わず手動確認の対象にする |

これ以外の項目があると、検証スクリプトが WARN を出します。

### 例

```json
{
  "id": "J1-EQ-0001",
  "grade": 1,
  "unit": "equation",
  "category": "移項",
  "difficulty": 1,
  "question": "4x-7=13",
  "answerLines": ["4x-7=13", "4x=13-7", "4x=6", "x=\\frac{3}{2}"],
  "errorLine": 1,
  "errorType": "移項するときの符号ミス",
  "explanation": "左辺の $-7$ を右辺に移項すると、符号が変わって $+7$ になります。正しくは $4x=13+7$ です。",
  "correctSolution": ["4x-7=13", "4x=13+7", "4x=20", "x=5"],
  "hint": "項を移項すると、その項の符号はどうなりますか？"
}
```

## 4. 答案の書き方のルール

### 4-1. 「最初に間違えた行」の定義（厳守）

1. 答案は上から順に読みます。
2. **直前の行から、初めて数学的に誤った変形をした行**を `errorLine` にします。「最終的な答えが間違っている行」ではありません。
3. 誤った行より後の行は、**誤った式から正しく計算を続けます**。別の独立したミスを入れてはいけません。
4. 誤りの原因は、原則1か所にします。
5. 数学的に正しい別解や変形を、誤答扱いにしてはいけません。
6. index 0 は問題を再掲した行なので、`errorLine` に 0 は指定できません（1 以上）。

### 4-2. 行の形式

| 単元 | 1行目 | 2行目以降 |
|---|---|---|
| 正負の数・文字式（式の計算・式の値） | 問題の式（`=` なし） | `=` で始まる式を1つ（例 `=-5+8-6`）。1行に `=` を2つ以上書かない |
| 方程式 | 方程式 | 等式を1つ（`=` がちょうど1つ）。最終行は `x=数` の形 |

- 説明文（「両辺に10をかけると」など）は行に入れず、`explanation` に書きます。
- 行数は1行目を含めて **原則3〜5行**、簡単な問題は2行でも可、最大6行です（6行は WARN）。
- 「全部正しい」答案は全体の20〜30%、各単元10問中2〜3問を目安にします。

### 4-3. LaTeX の書き方

KaTeX で表示できる LaTeX で書きます。JSON の中ではバックスラッシュを `\\` と2つ重ねます。
自動検証が読める記法は次のとおりです。**これ以外の記法を使うと、その行は「手動確認」になります。**

| 書きたいもの | 書き方 |
|---|---|
| かける・わる | `\times` `\div`（`\cdot` も可） |
| 分数 | `\frac{分子}{分母}`（`\dfrac` も可） |
| かっこ | `( )`、大きなかっこは `\left( \right)`、中かっこは `\{ \}` または `\left\{ \right\}`、`[ ]` |
| 累乗 | `x^2`、`(-3)^2`、2桁の指数は `x^{10}` |
| 小数 | `0.15` |
| 文字 | 半角英字1文字（`x` `a` など） |
| 暗黙のかけ算 | `3x`、`2(x+1)`、`\frac{1}{2}x`、`ab` |

自動検証は、中学校の慣習に合わせて次の順に計算します。

- 累乗 → 暗黙のかけ算（`3y` や `2(x+1)` をひとかたまりと見る）→ `\times` `\div`（左から順）→ `+` `-`
- 先頭のマイナスは累乗の外側にかかります（`-3^2 = -9`）。

`6\div2(1+2)` のように、読み方が人によって分かれる式は使わないでください。

### 4-4. explanation・hint・instruction

- 数式は `$...$` で囲みます（例 `"$-(-8)$ は $+8$ になります"`）。
- 「2行目」のような行番号は書かず、式そのもので誤りの箇所を示します（画面によって行番号の数え方が変わる可能性があるため）。
- 誤答の解説では、「どこが・なぜ誤りか」「正しくはどうなるか」を書きます。必要に応じて「ほかの部分は正しくできている」ことにもふれます。
- 全部正しい答案の解説は「すべての行が正しい計算です。」で始め、間違えやすいポイントを説明します。
- ヒントは答えを直接言わずに、確認すべき箇所を問いかける形にします。

## 5. 難易度の基準

| difficulty | 表示 | 目安 |
|---|---|---|
| 1 | ★ | 基本的な計算。途中式が短く、誤りを見つけやすい |
| 2 | ★★ | 標準的な計算。符号・分配法則などの基本原則の理解が必要。3〜4行の答案が中心 |
| 3 | ★★★ | 複数段階の計算。分数・小数・累乗も扱う。誤りを見つけるのにある程度の計算力が必要 |
| 4 | ★★★★ | 発展的な計算。紛らわしい変形や見落としやすい誤りを含む。正しい別解の答案も出題する |

行数だけで決めず、計算そのものの難しさと誤りの見つけにくさを合わせて判断します。

## 6. 検証と手動レビューの手順

1. データを編集する。
2. `npm run validate:verbose` で、各行の判定（`≡` 等価 / `≠` 等価でない / `?` 判定不能）を確認する。
3. `npm run serve` で開発者用プレビュー（`http://localhost:8080/preview.html`）を開き、表示を確認する（`?reveal=1` で正解・解説を最初から表示）。ゲーム画面（`/`）でも実際に解いて確かめる。
4. 下の「手動確認チェックリスト」を確認する。
5. `node tools/review-stamp.js --reviewer "名前" [--note "メモ"] ID ...` で、レビュー済みとして記録する。
6. `npm test` が通ることを確認する（レビュー記録が最新でないとエラーになります）。

レビュー記録には、問題データの内容のハッシュ（SHA-256）を一緒に保存します。そのため、レビュー後に問題を1文字でも変えると「要再レビュー」になります。

### 手動確認チェックリスト

自動検証では保証できないので、人が確認する項目です。

- [ ] **正しい答え**：`correctSolution` の最終行が答えとして正しく、答えの形（約分・整理）も適切か
- [ ] **誤り行の一意性**：指定した行が「最初に計算規則を誤った行」で、ほかに誤りと受け取れる行がないか
- [ ] **誤答の自然さ**：中学生が実際にしそうな誤りか（わざとらしい誤り、偶然の計算違いではないか）
- [ ] **解説と誤りの一致**：`explanation` の内容が、実際の誤りと合っているか
- [ ] **ヒントの正確さ**：ヒントが数学的に正しく、答えを言いすぎていないか
- [ ] **表記・答えの形**：文字式の表記ルール（×の省略、係数の位置、指数）、1行1式などを守っているか
- [ ] **別解の妥当性**：正しい答案が `correctSolution` と違う方法で解いている場合、その方法が中学校の範囲で正しいか
- [ ] **難易度・カテゴリ**：難易度とカテゴリが基準に合っているか

## 7. 自動検証の内容（`tools/validate-questions.js`）

### 構造のチェック（ERROR）
- JSON として読み込めるか、`schemaVersion`、manifest との一致
- 必須項目があるか、各項目の型、未定義の項目（WARN）
- ID の形式・重複、ID と学年・単元の一致
- `grade`・`unit`・`category`・`difficulty` が定義済みの値か
- 行数の範囲、1行目が `question` と一致しているか
- `errorLine` の範囲（1 以上・行数未満）、`errorLine` と `errorType` の null の対応
- KaTeX で構文エラーなく表示できるか（`question`・各行・解説やヒントの中の `$...$`）

### 数学のチェック
- **式の計算**：となりの行どうしが等価かを、無作為に選んだ8個の有理数で、BigInt を使った厳密な分数計算で確かめます
- **式の値**：`substitution` の値を代入して、各行の値が一致するかを確かめます
- **方程式**：各行の解（1次方程式の解集合）が一致するかを確かめます
- そのうえで次を確かめます
  - 正しい計算過程は、すべての行が直前の行と等価か（ERROR）
  - 全部正しい答案は、すべての行が等価で、最終行が正しい答えと一致するか（ERROR）
  - 誤答の答案は、指定した行より前がすべて等価か、指定した行が直前の行と**等価でない**か、指定した行より後がすべて（誤った式と）等価か（ERROR）
  - 方程式の最終行が `x=数` の形か
  - 誤答の最終行が、たまたま正しい答えになっていないか（WARN）

### 手動確認（MANUAL）として明示されるもの
- 解析できない記法を使った行、1次ではない方程式、2種類以上の文字を含む方程式
- `verification.mode = "manual"` を指定した問題、自動検証にまだ対応していない単元
- 全部正しい答案の途中式が `correctSolution` と違う場合（別解の妥当性）
- 「文字式の表し方」の問題（表記ルールは自動判定できない）
- `correctSolution` の最終行に × や ÷ が残っている場合

### 問題全体の集計
- 単元ごとの問題数、「全部正しい」の割合、難易度とカテゴリの分布
- 同じ問題式の重複（WARN）、同じ単元で同じ `errorType` が3回以上（WARN）
