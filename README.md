# 計算ティーチャー！

> キミは計算ミスを見抜けるか！？

中学生向けの計算学習ゲームです。生徒が数学の先生になって、別の生徒が解いた答案から「**最初に間違えた行**」を見つけ、添削します。
正誤を当てるだけでなく、途中式を読み解きながら正しい計算規則を身につけることをねらいとしています。

## すぐに試す

Node.js 18 以上が必要です（開発時は v24 で確認）。

```bash
npm install          # KaTeX（検証スクリプト用）をインストール
npm run serve        # → http://localhost:8080/ でゲーム画面が開く
npm test             # 自動テスト一式（ブラウザ不要）
npm run test:ui      # ゲーム画面の操作テスト（Chrome または Edge が必要）
```

- ポート 8080 が使用中の場合は、`npm run serve -- 8081` のように別のポートを指定してください。
- 画面は `fetch` で JSON を読むため、`index.html` をダブルクリックで開く（file://）方法では動きません。GitHub Pages にそのまま置けば動きます（サーバーやデータベースは不要）。

| URL | 画面 | 対象 |
|---|---|---|
| `/`（`index.html`） | ゲーム画面 | 生徒 |
| `/preview.html` | 問題プレビュー | 開発者（生徒向け画面にリンクはありません。URL を直接入力するか、裏ワザで開きます） |

## 遊び方

1. **タイトル画面**で「トレーニング」を押します（右上の「？ 遊び方」で説明も見られます）。
2. **設定画面**で、単元・カテゴリ・難易度・問題数を選んで「添削スタート！」を押します。
3. **添削問題画面**で答案を上から読み、**最初に**計算を間違えた行をタップします。ミスがなければ「○ 全部正しい！」を選びます。
4. 「**添削する！**」を押すと答え合わせです。正解・不正解と、解説・正しい計算過程が表示されます。
5. 答え合わせのあと、「添削する！」ボタンが同じ位置で赤い「**次の問題へ**」ボタンに変わります。全問解き終わると（最後は「結果を見る」）**トレーニング結果**（正解率・出題数・正解数・まちがい数・ひとこと評価）が表示されます。
6. 結果画面の問題カード（1問目・2問目…）をタップすると、**その問題だけをもう一度解けます**。解き終わったら「結果にもどる」で結果画面に戻ります。

「最終的な答えが間違っている行」ではなく、「**最初に計算規則を誤った行**」を探すゲームです。

タイトル画面からは、次の3つのモードと記録を選べます。

| モード | 内容 |
|---|---|
| トレーニング | 単元・カテゴリ・難易度・問題数を選んで、ヒントと解説つきでじっくり練習 |
| ⏱ タイムアタック | 90秒（＋ロスタイム5秒）で何問添削できるか。行をタップした瞬間に判定。3回ミスでゲームオーバー。公式（自己ベスト・称号）とカスタム（集中練習）がある |
| 🎓 ティーチャー認定試験 | 単元ごとの5段階の試験。合格するとティーチャーランクが上がる |
| 📖 ストーリー | 「記録を見る」画面から開く、おまけの物語（全12話）。ゲームで正解した数（累積正解数）に応じて新しい話が読めるようになる |
| 🏆 記録を見る | 公式タイムアタックの記録・カスタムの履歴・認定状況 |

### 単元・カテゴリ・難易度・問題数の選び方

設定画面は「単元 → カテゴリ → 難易度 → 問題数 → 添削スタート！」の順に並んでいます。

- **単元**：1つ選びます。中2・中3の単元は、データを追加して `data/manifest.json` に1行足すと、自動で一覧に出ます。
- **カテゴリ**：単元の中の計算分野（例：正負の数なら「加法・減法」「乗法・除法」「累乗」「四則混合」）を、いくつでも選べます。
  - カテゴリをタップするたびに、選択・解除が切り替わります。選んでいるカテゴリは ✔ と色付きの枠で示します。カテゴリ・難易度のボタンには問題数を書きません（トレーニング・カスタムタイムアタックとも。出題できる問題数は設定画面の下にまとめて表示します）。
  - 「すべて選択」ボタンで全カテゴリを選びます。**全カテゴリが選ばれているときだけ**「すべて解除」に変わり、押すと全部の選択を外します（難易度と同じ動き）。
  - **単元を選ぶと、その単元のカテゴリがすべて選ばれた状態になります。** 前の単元の選択は引き継ぎません（同じ単元を選び直したときは、選択をそのまま保ちます）。
  - カテゴリを1つも選んでいないときは、開始できません。
  - カテゴリの一覧は画面のプログラムに書かず、`js/lib/question-schema.js` の定義と、問題データの `category` から作ります。定義の順に並べ、定義にないカテゴリが問題データにあれば後ろに足します。新しいカテゴリや中2・中3の単元を追加しても、そのまま一覧に出ます。
  - スマートフォンでは2列で並べ、長いカテゴリ名は折り返して見切れないようにしています。
- **出題条件**：「選んだ単元」かつ「選んだカテゴリのどれか」かつ「選んだ難易度のどれか」に当てはまる問題を出題します（カテゴリどうし・難易度どうしは「または」、カテゴリと難易度の間は「かつ」）。
  - 例：正負の数で、カテゴリ「加法・減法」「累乗」、難易度「★★」「★★★」を選ぶと、「加法・減法」または「累乗」の問題のうち、★★または★★★のものが出題されます。
- **難易度**：★〜★★★★をいくつでも選べます。押すたびにその難易度の選択・解除が切り替わります。初期状態はすべて選択です。
  - 難易度のボタンの横に「すべて選択」ボタンがあり、押すと全難易度を選びます。**全難易度が選ばれているときだけ**「すべて解除」に変わり、押すと全部の選択を外します。
  - 選んだ単元に問題がない難易度は、押せない表示になります。
  - 難易度を1つも選んでいないときは、開始できません。
- **問題数**：スライダーで **1問から最大数まで** 1問単位で選べます（初期値5問）。両側の −／＋ ボタンでも1問ずつ変えられます。
  - 最大数は「選んだ単元・カテゴリ・難易度で出題できる問題数」です（データに不整合がある問題は除きます）。カテゴリや難易度を変えると最大数も変わります。例：正負の数の「累乗」だけを選ぶと最大25問、さらに難易度を★だけにすると最大6問になります（現在の問題データの場合）。
  - 最大数が減っても、選んだ数（希望の問題数）は覚えておきます。条件を戻して最大数が増えれば、元の数に戻ります。選んだ数が最大数を超えるときは最大数を出題し、同じ問題をくり返して数を埋めることはしません。
  - 出題できる問題が0問のとき（カテゴリや難易度を1つも選んでいないとき、選んだカテゴリにその難易度の問題がないときなど）は、スライダーと「添削スタート！」を使えません。理由は設定画面の下に表示します。
- **設定の引き継ぎ**：結果画面の「もう一度チャレンジ」は、単元・カテゴリ・難易度・希望の問題数をそのまま使い、問題の順番だけをシャッフルし直して始めます。「単元選択に戻る」でも、直前の設定が残っています。

### 操作のルール

- 答案の **1行目は問題の式の再掲**なので、選べません（ボタンの枠がなく、少し薄い色で表示）。選べるのは2行目以降です。
- 行は1つだけ選べます。別の行を押すと選び直し、同じ行をもう一度押すと解除です。
- 行を選ぶと「全部正しい！」の選択は解除され、「全部正しい！」を選ぶと行の選択は解除されます。
- 誤操作を防ぐため、行をタップしただけでは判定しません。**選んでから「添削する！」を押す2段階操作**です。何も選んでいないときは「添削する！」を押せません。
- 1問につき判定は1回だけです。判定後は答案の行もボタンも押せなくなります。
- 「やめる」ボタンやブラウザの「戻る」を押すと確認ダイアログが出ます。「やめる」を選ぶとタイトルに戻ります（途中経過は保存しません）。「つづける」なら、選択状態もそのまま続けられます。

### 生徒の答案と並べて表示

- 答え合わせのあと、「正しい計算過程」の下の「⇆ 生徒の答案と並べて表示」を押すと、ポップアップが開きます。
- 全部正しい答案のときは「この答案は全部正しい答案です」と表示します。「（正しい計算過程は別の解き方の例です）」は、生徒の答案と正しい計算過程の式がちがう（別解の）ときだけ付けます。
- 「行番号｜生徒の答案｜正しい計算過程」の3列で、**同じ行どうしを横に並べて**表示します。生徒の答案の最初の誤り行は、黄色の背景と赤い枠で強調します。方程式では、列ごとに「＝」の位置をそろえます。
- **スマートフォンの縦画面**では、ポップアップを右に90°回転して表示します（端末を横向きに持つと読みやすい向き）。横に並べるための幅を確保するためです。iPad やパソコン、スマートフォンの横画面では回転しません。
- 「閉じる」ボタン（または Esc キー、ブラウザの「戻る」）で閉じます。

### 効果音

ボタンを押したときや、正解・不正解のときに、短い効果音が鳴ります。音は `js/sound.js` が Web Audio API で合成するので、音声ファイルは使いません。

| 場面 | 音 | 長さ |
|---|---|---|
| 答案の行・「全部正しい！」を選ぶ（解除も） | 軽く明るいクリック | 約0.07秒 |
| 「添削する！」 | スタンプを押すような「ポン」 | 約0.13秒 |
| 添削成功 | 明るい上昇チャイム（ピンポーン♪）。スタンプ音の0.12秒後に続けて鳴る | 約0.53秒 |
| 添削失敗 | 低めの2音の控えめなブザー。スタンプ音の0.12秒後に続けて鳴る | 約0.37秒 |
| ヒントを開く（閉じるときは鳴らない） | 軽いキラキラ | 約0.32秒 |
| 「次の問題へ」「結果にもどる」 | 軽いページ送り | 約0.13秒 |
| 「添削スタート！」「もう一度チャレンジ」、結果画面からの解き直し | 明るい短いチャイム | 約0.57秒 |
| 結果発表（通常） | 和音を含む終了チャイム | 約0.86秒 |
| 結果発表（全問正解） | 豪華なファンファーレ（通常の終了音は重ねない） | 約1.42秒 |
| 画面の移動・単元／カテゴリ／難易度の選択・やめる確認・並べて表示の開閉 | とても小さなクリック | 約0.06秒 |

- **ON/OFF**：タイトル画面右上の「⚙ 設定」→「効果音」のスイッチで切り替えます。プレイ中は画面上部の 🔊（OFF のときは 🔇）ボタンでも切り替えられます。OFF にすると、鳴っている音もすぐに止まります。
- **音量**：設定画面のスライダーで 0〜100％（初期値50％）。動かすとすぐに反映され、指を離すと確認の音が鳴ります。0％は無音です。「♪ 音をためす」で正解音を試せます。
- 設定画面のいちばん下には「🧪 KEC数学科ラボへ」（https://taka-t-p.github.io/math-app-portal/ へ移動）と「🗑 記録を消す」があります。「記録を消す」は「本当に消しますか？」の確認で「はい」を選んだときだけ、タイムアタックの記録・カスタム履歴・認定試験の合格状況をすべて消します（効果音の設定は残ります。新しい版のアプリで保存された記録は消しません）。
- **保存**：ON/OFF と音量は、ブラウザの `localStorage`（キー `calcTeacher.sound`）に保存され、次に開いたときも使われます。保存するのは音声の設定だけで、プレイの記録は保存しません。保存できない環境（プライベートモードなど）でも、そのまま初期設定で遊べます。
- **騒がしくならない工夫**：
  - 同じ音を短い間隔で何度押しても、間引いて1回だけ鳴らします（連打対策）。
  - 同時に鳴る音は最大6つまでで、すべての音は最後に音量を抑える処理（コンプレッサー）を通ります。
  - 正解音・結果発表などの長い音は、次の長い音を鳴らすときや画面を移るときに、短くフェードアウトさせます。前の画面の音が残りません。
  - 音の鳴り始めと終わりに短いフェードを入れて、「プツッ」という音が出ないようにしています。

#### 対応ブラウザと音声再生の制限

- Windows の Chrome・Edge、iPad／iPhone の Safari、Android の Chrome で動くように作っています（`AudioContext` と、古い Safari の `webkitAudioContext` の両方に対応）。
- iPhone・iPad の Safari などは、利用者が画面を操作する前に音を鳴らすことを許可していません。そのため、**最初にタップ（またはクリック・キー入力）したときに音声の仕組みを準備・再開**します。起動しただけで音が鳴ることはありません。
- 音を鳴らせない環境や、再生に失敗したときも、ゲームはそのまま進みます（採点や進行には一切影響しません）。
- iPhone 本体の消音スイッチ（サイレントモード）がオンのときは、Safari の仕様で効果音が鳴らないことがあります。
- 音が実際に聞こえるか、音量や音色が適切かは、自動テストでは確かめられません。**授業で使う端末（iPad など）で一度鳴らして確認**してください。

### 累積正解数の数え方

- トレーニング（結果画面からの1問の解き直しも）・公式／カスタムのタイムアタック・ティーチャー認定試験で、**正解が確定した時点で1問につき1ふやし、すぐに保存**します（結果画面まで待ちません）。単元は問いません。正答版・誤答版どちらの答案でも、正しく添削できれば正解です。

- 以前の記録（`calcTeacher.records`）からは推測せず、ストーリーモードを入れた時点の0から数えます。

### BGM（BGMer の SHORT 版7曲）

| ID | 曲名 | 主な用途 |
|---|---|---|
| daily | かのうせいのかたまり | 普段の教室、明るい日常 |
| friendship | きみは相棒 | 努力、仲間、前向きな会話 |
| sad | 涙の結晶 | 落ち込み、不安、挫折 |
| growth | きみはやりとげた | 成長、励まし、達成感 |
| exam | 漢太鼓 | リアル入試、緊張感 |
| congratulations | こもれびの手紙 | 合格報告、感動 |
| ending | 僕らのエピローグ | 最終話エンディング |

- **ファイル**：`assets/story/bgm/<ID>.mp3`（各1.7〜2.6MB、合計約15MB）。`tools/build-story-assets.js` で、元の MP3 の先頭の無音（0.4〜1.0秒）と末尾の無音（0.4〜5.7秒）を切り、ラウドネスを −16 LUFS にそろえました（漢太鼓は元が非常に大きく −5.5 LUFS・ピークが 0dB をこえていたため、会話を読みやすいよう −19 LUFS に下げています）。曲の長さとループ位置は `episodes.json` の `bgm.tracks` に書き込みます。
- **ループ**：元の MP3 は先頭と末尾に無音があり、`audio.loop = true` では最大6秒ほど途切れるため、無音を切ったうえで、曲の終わりの1.2秒前から2つ目の audio 要素で曲の頭を鳴らし、**1.2秒のクロスフェード**でつなぎます。タイマーが間に合わずに曲が終わったときは、頭から再生し直します。
- **切りかえ**：シーンの区切りでだけ曲を変えます。同じ曲が続くときは再生を続け、別の曲のときは古い曲を約1秒でフェードアウト・新しい曲を約1秒でフェードインします。
- **再生する場面**：ストーリーの会話画面だけです。一覧・タイトル・ほかのモードでは流さず、会話画面を出ると止めます。画面が隠れたら一時停止し、戻ると続きから鳴らします。
- **設定**：設定画面の「ストーリーBGM」で ON/OFF と音量（0〜100%、初期値25%）、会話画面の「♪ BGM」ボタンでも ON/OFF できます。効果音の設定とは独立しています（効果音を OFF にしても BGM は鳴り、その逆も同じ）。
- **iPad などの自動再生の制限**：話を開くボタンを押した操作の中で再生を始め、ループ用の2つ目の audio 要素もその操作の中で準備します。そのため一覧を開いたときに12話分のデータ（各5KB程度）を先に読み込みます。音量とフェードは Web Audio の GainNode で変えます（iPad の Safari は audio 要素の volume を変えられないため）。
- 音声ファイルは、その曲を鳴らすときに初めて読み込みます（起動時に7曲を読み込みません）。ファイルがない・再生できないときも、ストーリーはそのまま進みます。
- **利用規約**（https://bgmer.net/terms/ を実装時に確認）：無料・商用利用も可、利用報告は不要、アレンジ・改変（今回の無音の削除・音量の調整・再エンコード）も可、再配布も禁止されていません。クレジットは任意ですが、設定画面の「使用している音楽（クレジット）」に「音楽：BGMer」と7曲の曲名を、ストーリー一覧の下にも「音楽：BGMer」を記載しています。自作曲と偽ることや、音源の販売などは禁止されています。

## 第7段階：正答・誤答の答案パターン

これまでは、1つの問題 ID の答案はいつも同じでした（誤りのある答案の問題は、いつも誤答。正しい答案の問題は、いつも「全部正しい！」）。そのため、同じ問題をくり返すと「この問題は全部正しい」と答えを覚えられてしまいます。第7段階では、**同じ問題でも、出題のたびに正しい答案（正答パターン）と誤りのある答案（誤答パターン）を抽選**して出すようにしました。

- 問題 ID・問題数（800問）は変えていません。答案パターンは問題の数として数えません。
- ゲームのルール（得点・連続正解・制限時間・ミスの回数・認定試験の配分と合否・ランク）、記録の形式、引継ぎコードは変えていません。

### 問題の分類

| 分類 | 問題数 | 答案パターン | 出題 |
|---|---:|---|---|
| 誤りのある答案の問題 | 575 | 登録している誤答（`wrong-1`）＋ 模範解答 `correctSolution` を答案にした正答（`correct-1`） | 25%で正答・75%で誤答 |
| 正しい答案で、模範解答と同じ問題（A） | 221 | 登録している正答（`correct-1`）＋ **今回追加した誤答**（`variants` の `wrong-1`） | 25%で正答・75%で誤答 |
| 正しい答案で、別解の問題（B） | 4 | 登録している正答だけ（変えていない） | いつも正答 |
| **合計** | **800** | **1596個** | |

- 正しい答案の225問を、答案（`answerLines`）が模範解答（`correctSolution`）と同じか（A）、違う解き方か（B：別解）で分けました。B の4問（J1-PN-0010・J1-PN-0015・J1-EQ-0003・J1-EQ-0016）は、分配法則・小数を分数に直す・文字の項を右辺に集める・両辺に20をかける別解を見せるための問題なので、そのまま「全部正しい！」で出します。
- 分類の一覧（225問の ID・分類・判定理由・誤答の追加の有無・数学講師の確認が必要か）は `docs/variant-classification.csv`・`docs/variant-classification.json` にあります。`node tools/question-report.js --classify 出力先.csv`（または `.json`）で作り直せます。
- 単元ごとの追加数：正負の数26・文字式28・方程式26・式の計算28・連立方程式28・展開・因数分解29・平方根28・2次方程式28（計221）。

### 正答・誤答の確率

- 確率は `js/question-variants.js` の **`CORRECT_VARIANT_RATE = 0.25`** の1か所で決めています（全モード共通）。
- 問題ごとに `0以上1未満` の乱数 u を1つ引き、**u < 0.25 なら正答パターン、それ以外は誤答パターン**です（同じ種類のパターンが複数あるときは、その中から等しい確率で選びます）。
- 問題ごとに独立に抽選し、1回のプレイの正答の数をそろえる補正はしません（5問とも誤答や、3問正答の回もあります）。
- **割合の意味のちがい**：「登録データの『全部正しい！』」は、問題データの `errorLine` が `null` の問題の割合で、**28.1%（225/800問）のまま**です。一方、プレイで「全部正しい！」が正解になる**理論上の出題率は 25.4%** です（切り替える796問は25%、別解の4問は100%。正負の数・方程式は26.5%、ほかの単元は25.0%）。`npm run validate`・`npm run report:questions` は両方を区別して表示します。

### 問題データの形

既存の項目（`answerLines`・`errorLine`・`errorType`・`explanation`）は、そのまま「登録データの答案」として残しています。追加した項目は次の2つです（どちらも任意。詳しくは `docs/question-data-spec.md`）。

| 項目 | 使う問題 | 内容 |
|---|---|---|
| `variants` | 正しい答案の問題（A） | 追加の誤答パターンの配列。`id`（`wrong-1` など）・`answerLines`・`errorLine`・`errorType`・`explanation` |
| `correctExplanation` | 誤りのある答案の問題（任意） | 正答パターンを出したときの「計算のポイント」。省略すると、その問題でよくある誤り（`errorType`）にふれた共通の文を使う |

```json
{
  "id": "J1-PN-0003",
  "answerLines": ["\\frac{2}{3}-\\frac{5}{6}-\\left(-\\frac{1}{4}\\right)", "=\\frac{2}{3}-\\frac{5}{6}+\\frac{1}{4}",
                  "=\\frac{8}{12}-\\frac{10}{12}+\\frac{3}{12}", "=\\frac{1}{12}"],
  "errorLine": null,
  "correctSolution": ["（answerLines と同じ）"],
  "variants": [
    { "id": "wrong-1",
      "answerLines": ["\\frac{2}{3}-\\frac{5}{6}-\\left(-\\frac{1}{4}\\right)", "=\\frac{2}{3}-\\frac{5}{6}+\\frac{1}{4}",
                      "=\\frac{8}{12}-\\frac{10}{12}+\\frac{1}{12}", "=-\\frac{1}{12}"],
      "errorLine": 2, "errorType": "通分で分子に数をかけ忘れた誤り", "explanation": "$\\frac{1}{4}$ を分母 $12$ に…" }
  ]
}
```

誤りのある答案の問題の正答パターンは、データに書かずに `correctSolution` から作ります（同じ答案を2か所に書かないため）。

### プレイ・採点・結果への影響

- 出題する問題（ID）を今までどおりに選んだあと、**別の乱数**で答案パターンを抽選します。答案パターンの抽選は出題順に影響しません（`?seed=` を付けると、出題順も答案パターンも再現できます）。
- 抽選した答案は「出題した答案」として保持し、**採点・解説・誤りの種類・結果画面・並べて表示は、すべて出題した答案パターン**で行います（正答パターンなら「全部正しい！」が正解で「計算のポイント」を表示、誤答パターンならその行が正解で「まちがいの理由」を表示）。

- ヒントは正答版・誤答版の両方で出すので、誤答の行にしかない式を示さない書き方に直しました（26問。誤答の行だけに出てくる数式がヒントにあると、検証スクリプトが WARN を出します）。

### 答案の書き方（中2・中3）

- 連立方程式は、2つの式を並べた行（`cases`）や加減法の筆算（`array`。`+)`・`-)` と横線）を**1行**として扱い、その行全体をタップして添削します。最終行は `x=3,\ y=2` の形です。`A=B=C` の形の問題もあります。
- 2次方程式は、各行が方程式です（`(x-5)(x+2)=0`、`x+3=\pm\sqrt5` など）。最終行は `x=5,\ -2` や `x=3\pm\sqrt5` の形です。
- 「答えの形の誤り」（例：`3(ab+2b)` で終わる、`\sqrt{72}` を `2\sqrt{18}` で終わる、`x=\pm\sqrt{12}` で終わる）は、その行を最終行にして誤り行にしています。
- 詳しい書き方は `docs/question-data-spec.md` の「4-2. 行の形式」にまとめました。

### 数式検証の拡張（`js/lib/math-verify.js`・`tools/validate-questions.js`）

| 対象 | 方法 |
|---|---|
| 平方根 | `a\sqrt{b}`（a は有理数、b は平方因数のない自然数）の形の数を BigInt で厳密に計算。分母の根号は共役な数をかけて有理化して比べる |
| 2次方程式 | 各行を「解の集合」に直して比べる（判別式から実数解を厳密に求める。`\pm` と「または」は2つの式に分ける） |
| 連立方程式 | 1行目から解を1組求め、各行の式がすべてその解で成り立つかで正誤を判定（加減法で文字を消した式は元の式と同値ではないため）。誤りのあとの行と誤った式は、生徒の最終行の答えで成り立つかを確かめる。`A=B=C` は `A=C`・`B=C` として扱う |
| 答えの形 | 整理された多項式／展開した形／因数分解しきった形／根号のいちばん簡単な形／2次方程式の解の簡単な形を、等価性とは別に確かめる。正しい答案の最終行がこの形でなければ ERROR |
| 答えの形の誤り | 最終行が「直前の行と等価で、答えの形だけが違う」ときに限り、正しい誤答として受け付ける |

## 第5段階：引継ぎコードで記録を別の端末へ

公式タイムアタックとティーチャー認定試験の記録（のちにストーリーの累積正解数も追加）を、短い**引継ぎコード**にして、別の端末へ移せるようにしました。サーバー・データベース・ログインは使わず、ブラウザの中だけで処理します（GitHub Pages のままで動きます）。コードの作成・読み込みは `js/record-transfer.js`、記録の置き換えと保存は `js/records.js` が担当します。

### 使い方

**元の端末**（記録を渡す側）

1. タイトル画面右上の「⚙ 設定」を開く。
2. 「記録の引継ぎ」の「📋 引継ぎコードをつくる」を押す。
3. 「引継ぎコードを発行する」を押す。
4. 「📋 コードをコピー」を押す（「コピーしました！」と出ます）。コピーできない端末では、コードが選択された状態になるので、長押しなどでコピーしてください。
5. メール・メッセージなどで、引き継ぎたい端末にコードを送る。

**引継ぎ先の端末**（記録を受け取る側）

1. 「⚙ 設定」の「📥 引継ぎコードを読み込む」を押す。
2. コードを貼り付けて「コードを確認する」を押す（この時点では記録は変わりません）。
3. 「引き継ぐ記録を確認」で、単元ごとの最高スコア・称号・認定の状況と、ストーリーの累積正解数（第何話まで読めるか）を確かめる。
4. 「記録を引き継ぐ」を押すと、記録が置き換わります。「🏆 記録を確認する」で記録画面を開けます。

### 引き継ぐ記録・引き継がない記録

| 記録 | 引継ぎコード | 引継ぎ先での扱い |
|---|---|---|
| 公式タイムアタック（単元ごと）：最高スコア・達成日時・最大連続正解数・プレイ回数 | 入れる | **コードの内容に置き換える** |
| ティーチャー認定試験（単元ごと）：最高クリア試験・各試験の挑戦回数・初クリア日時 | 入れる | **コードの内容に置き換える** |
| ストーリーの累積正解数（CT2） | 入れる | **コードの内容に置き換える**（その数で話が解放される）。CT1 のコードには入っていないので、そのときは引継ぎ先の数のまま |
| ストーリーの既読・登場人物の名前・裏ワザの全話解放・ストーリーBGM の設定 | 入れない | 引継ぎ先のものをそのまま残す |
| 称号（10段階）・ティーチャーランク・試験の解放状況 | 入れない | 最高スコア・最高クリア試験から、既存の `time-attack.js`・`certification.js` で計算し直す |
| カスタムタイムアタックの履歴 | **入れない** | **引継ぎ先の履歴をそのまま残す** |
| 効果音の ON/OFF・音量 | 入れない | 引継ぎ先の設定をそのまま残す（`calcTeacher.sound` にはふれない） |
| プレイ途中の状態・トレーニングの選択条件・生徒キャラクターの表示 | 入れない | そのまま |

- **上書きのルール**：公式・認定の記録は、引継ぎ元と引継ぎ先を合体させず、**コードの内容で置き換えます**（コードにない単元の公式・認定記録は、引継ぎ先からなくなります）。引継ぎ先に公式・認定の記録（または累積正解数）があるときは、確認画面に「この端末の公式タイムアタック記録・ティーチャー認定試験の記録と、ストーリーの累積正解数を、引継ぎコードの内容に置き換えます。」と注意を出します。
- **カスタム履歴を残すしくみ**：`calcTeacher.records` 全体をコードの内容で上書きせず、「引継ぎ先のカスタム履歴」と「コードから復元した公式・認定記録」を組み合わせた新しい記録をメモリ上でつくってから保存します。
- **安全に保存するしくみ**：新しい記録を全部組み立ててから1回で保存し、保存した内容を読み戻して一致を確かめます。累積正解数（`calcTeacher.story`）を先に置き換え、公式・認定の記録が保存できなかったときは累積正解数も元に戻します。保存できなかったときは成功の表示を出さず、「記録を保存できませんでした。端末の設定や空き容量をご確認ください。」と表示して、この端末の記録を元のまま残します（一部だけ保存されることはありません）。新しい版のアプリで保存された記録がある端末では、上書きしません。
- コードをつくっても、元の端末の記録は変わりません。コードに有効期限はなく、同じ記録からはいつも同じコードになります（発行した時刻などは入れません）。記録が増えたら、もう一度つくると最新の記録のコードになります。
- このアプリがまだ知らない単元（新しいアプリでつくったコードの単元）の記録も、消さずにそのまま保存し、次の引継ぎにも含めます。

### コードの形式（CT2。CT1 も読める）

`CT2-` のあとに、記録を詰めたバイト列と CRC32（4バイト）を Base64URL（英数字と `-` `_`）で文字にしたものが続きます。`CT2` は**引継ぎコードの形式の版**で、記録の保存形式（`calcTeacher.records` の `version: 1`）とは別に管理しています。

- **CT2**（現在つくるコード）＝ CT1 の記録のバイト列のあとに、ストーリーの累積正解数（可変長整数）を足したもの。
- **CT1**（ストーリー追加前のアプリでつくったコード）も、これまでどおり読み込めます（累積正解数は「入っていない」として、引継ぎ先の数を変えません）。CT1 の形式は1バイトも変えていません（以前の版でつくったコードを固定のサンプルとしてテストしています）。
- CT2 のコードを、CT1 しか読めない古いアプリに読ませると「アプリを更新してから」のメッセージになります（壊れたコードとは区別します）。

| 短くする工夫 | 内容 |
|---|---|
| 必要な記録だけ | 公式・認定の記録と累積正解数だけを入れる。称号名・ランク名・クリア状況（最高クリア試験から決まる）・カスタム履歴は入れない |
| 項目名を書かない | JSON の項目名を使わず、決まった順に数を並べる |
| 数を短く | 数は可変長整数（小さい数は1バイト）。最高スコアやプレイ回数は2バイト程度 |
| 単元を番号で | 単元は固定の番号表（正負の数=1 … 2次方程式=8）。番号は今後も変えず、新しい単元は末尾に足す。番号表にない単元は単元IDの文字のまま入れる（並び順に依存しない） |
| 日時は差で | ミリ秒の精度のまま、ひとつ前の日時との差を入れる（記録の日時は近いことが多い） |
| 圧縮ライブラリなし | 追加のライブラリやブラウザ専用の圧縮機能は使わない（iPad Safari を含む、どのブラウザでも同じ結果） |

**実際のコードの長さ**（`node tools/test-transfer.js` で測定）

| 記録 | 文字数 |
|---|---:|
| 記録なし | 14 |
| 1単元（公式＋認定は第2試験までクリア） | 50 |
| 中1の3単元すべて（公式3単元、認定は第3・第2・最終試験までクリア） | 140 |
| 中1〜中3の8単元すべて（公式、認定は全単元で最終試験までクリア。日時がばらばら） | 486 |
| （参考）中1の3単元を JSON のまま Base64 にした場合 | 1,750 |

（CT2 で累積正解数を足しても、増えるのは1〜3文字程度です。累積正解数が127問以下なら1バイト、16,383問以下なら2バイト）

**読み込むときの確認**（コードは外から入ってくる信頼できないデータとして扱います）

- 貼り付けた文字の前後・途中の空白・改行・見えない文字は取り除きます（それ以外の文字を推測で直すことはしません）。
- 形式（`CT2-`／`CT1-`）、形式の版、チェック情報（CRC32。`CT2`（または `CT1`）の文字と記録のバイト列から計算）、累積正解数の範囲、データの構造、数の範囲、日時の範囲（2020〜2100年）、単元IDの形（英小文字・数字・ハイフン、40文字まで。`__proto__` などは拒否）、認定試験の矛盾（クリアしていない試験がある・まだ挑戦できない試験の記録・挑戦回数0 など）、入力とデータの大きさの上限を確かめます。`eval()` は使わず、表示する文字はすべてエスケープします。
- 確かめられなかったときは、記録を変えずに次のメッセージを出します。

| 状況 | メッセージ |
|---|---|
| 形式が違う | 引継ぎコードが正しくありません。もう一度コピーしてください。 |
| 途中で切れている | コードの一部が足りないか、正しくコピーできていません。 |
| 新しい形式・知らない単元番号 | このコードは現在のアプリでは読み込めません。アプリを更新してからお試しください。 |
| 壊れている・内容が矛盾している | 記録を読み込めませんでした。元の端末でコードをつくり直してください。 |

- チェック情報は、コピーのし忘れ・途中で切れた・入力ミス・文字化けを見つけるためのもので、暗号化や改ざん防止ではありません。コードを持っている人は記録を読み込めるので、画面でも「自分の端末以外には送らないでください」と案内しています。

## 第4段階：中1の問題300問化と品質検証の強化

中1の3単元を各100問、合計300問にしました（第3段階までの48問に252問を追加）。問題の数だけでなく、カテゴリ・難易度・「全部正しい！」の割合・最初の誤り行の位置がかたよらないようにし、1問ずつ自動検証と AI によるレビューを行いました。ゲームのルール（得点・試験の配分・記録の形式）は変えていません（その後、ご要望により公式タイムアタックの難易度の出題順と称号を変更しました。「第3段階」の節の「出題」「称号」を参照）。

### 問題数と内訳（3単元とも同じ）

|---|---:|---:|---:|---:|---:|---:|
| カテゴリ1（加法・減法／文字式の表し方／移項） | 7 | 6 | 6 | 6 | 25 | 7 |

### 問題の作り方・確かめ方

252問を一度に作らず、**10〜12問ずつ24のバッチ**（単元・カテゴリ・難易度ごと）に分けて、次の順で追加しました。原稿は `tools/data-additions/stage4/batch-01-pn-addsub.js` 〜 `batch-24-eq-fraction.js` にあります。

1. 不足しているカテゴリ×難易度と、誤り行の位置・「全部正しい！」の数の目標をもとに、問題案を作る。誤りの種類と式の形が前の問題と重ならないようにする。
2. バッチの原稿（JSON と同じ形）を書く（`stage4/q.js` の補助関数で、1行目の問題の再掲などを自動で入れる）。
3. `node tools/data-additions/stage4/check-batch.js <バッチ>` で、**正式なデータに入れる前に**確認する。
   - `validate-questions.js` と同じ自動検証（必須項目・KaTeX・各行の等価性・最初の誤り行・誤りのあとに別の誤りがないか・正しい計算過程）
   - ID の重複、同じ問題式の重複
   - 類題候補（同じカテゴリで、式の形・誤り行・errorType が同じもの）
4. 解説・ヒントが誤りと合っているか、誤答が自然か、難易度が妥当かを読んで確かめ、直す。
5. `node tools/data-additions/stage4/add-batch.js <バッチ>` で追加する。確認 → `append-questions.js`（第3段階からの追記スクリプトをそのまま使用）で末尾に追記 → **既存の問題が1問も変わっていないことを確認** → AI によるレビューとして記録、の順に行い、どれかで問題があれば止まります。

途中で見つかって直したもの（例）：既存の問題と同じ方程式だった1問（`J1-EQ-0008` と同じ）、既存の問題とほぼ同じ形の正しい答案だった1問、解説の言い回し、6行になった正しい計算過程、分数の代入値の書き方。

### レビューの状況（AI と数学講師の区別）

**数学的な誤り（ERROR）と、出題バランスの警告（WARN）は分けています。** WARN が出ても、数学的に正しい問題を自動で書き換えたり除外したりはしません。これに合わせて、`validate-questions.js` から「同じ errorType が3回以上」という WARN を外し、errorType のかたよりは集計スクリプトで（単元の誤答に占める割合で）確かめるようにしました。`validate-questions.js` の WARN は、データそのものの注意点（未定義の項目・6行の答案など）だけになります。

現在の結果：**300問すべて完成（ERROR 0 件・バランスの WARN 0 件）**。

### タイムアタック・認定試験への影響

- **トレーニング**：出題の仕組みは変えていません。問題数スライダーの最大は選んだ条件の問題数（単元全体なら100問）になります。300問でも、条件のしぼり込みとカテゴリ一覧は一瞬で終わります（テストで確認）。
- **タイムアタック**：第4段階の問題追加では、ルール・得点計算・記録の基準を変えていません（当時は60秒・3回ミスでゲームオーバー・190+10n 点・公式とカスタムの区別。その後、ご要望により制限時間を90秒＋ロスタイム5秒に、得点を単元ごとの基礎点＋連続正解ボーナスにしました）。そのあと、ご要望により**公式タイムアタックの難易度の出題順**と**称号（10段階）**を変更しました（「第3段階」の節の「出題」「称号」を参照）。各難易度の問題が25問ずつあるので、決められた順の難易度で出しても、★★★・★★★★の問題は25問を出し終えるまで重複しません。
- **認定試験**：試験の配分・合格条件・解放条件・ランクは変えていません。各難易度の問題が25問ずつになったので、同じ試験でも挑戦するたびに違う問題構成になります（30回の挑戦で28通り以上、使われる問題は必要数の3倍以上になることをテストで確認）。難易度の中でカテゴリがかたよらない仕組みも、そのまま働いています（例：文字式の最終試験の★★★★4問は、毎回4つのカテゴリから1問ずつ）。
- **注意**：問題を増やしたことで、第3段階までの公式記録（16〜17問の中から出題されていたころの記録）と、これからの記録では、出題される問題の範囲が違います。記録は消さずにそのまま比べていますが、厳密には条件が同じではありません。将来、出題ルールや得点計算を変えるときは、記録に「ルールの版」を持たせることを検討します（今回は記録の形式を変えていません）。

## 第3段階：タイムアタック・認定試験・記録

### ⏱ タイムアタック（90秒）

90秒で、できるだけ多くの答案を正しく添削するモードです（第3段階では60秒でしたが、ご要望により90秒にしました）。テンポを大事にするため、トレーニングとは操作が違います。

- 答案の2行目以降、または「○ 全部正しい！」を**タップした瞬間に判定**します（「添削する！」ボタンはありません）。
- 正解・不正解を約0.6秒見せてから、自動で次の問題に進みます（ご要望により、以前の約0.3秒の2倍にしました）。この間のタップは受け付けません（連打による二重回答・次の問題への誤回答を防ぐため）。
- ヒントは使えません。くわしい解説は、終了後の結果画面で問題ごとに確認できます（解説を見てもスコアや記録は変わりません）。
- 開始時に「3・2・1・START!」のカウントダウンがあり、**START! の瞬間から90秒**を数えます。カウントダウン中は時間が減りません。「3・2・1」の数字の下には「タップした瞬間に判定！」「3回ミスでゲームオーバー！」と表示します。
- プレイ中の答案には「生徒の答案」の見出しや操作の説明を出さず、問題と答案だけを表示します（すばやく添削できるように）。
- 残り時間は数字とゲージで表示し、**残り10秒で警告**（数字が赤くなり警告音）、**残り5秒から強調表示**（数字が脈打つ）します。一時停止はありません。
- 時間は「START! からの実際の経過時間」で計算します（`performance.now()`）。タイマーの回数では数えないので、ブラウザが裏に回っても実際の時間どおりに減ります。
- 問題の左上のバッジは「第1問」「第2問」…と表示します。
- **ロスタイム**：残り0秒になった瞬間には終わらず、そのとき表示している問題だけ、さらに**5秒**回答できます。5秒以内に回答する（正解でも不正解でも記録・得点される）か、回答しないまま5秒たつと終了し、タイムアップ音のあと結果画面へ進みます。ロスタイム中も残り時間は「0秒」のままで、カウントダウンや警告の効果音は鳴りません。正誤の演出中に0秒になったときは、次の問題を出さずに終了します（3回ミスで先に終わったときは「ゲームオーバー」の表示と音）。
- 時間の設定は `js/time-attack.js` の `CONFIG`（`durationMs: 90000`・`lossTimeMs: 5000`・`feedbackMs: 600`）にまとめています。
- 「やめる」やブラウザの「戻る」では確認ダイアログが出ます。途中でやめた回は記録しません。

#### 公式とカスタムの違い

| | 公式タイムアタック | カスタムタイムアタック |
|---|---|---|
| 選ぶもの | 単元だけ | 単元・カテゴリ（複数）・難易度（複数） |
| カテゴリ・難易度 | 全カテゴリ・全難易度（★〜★★★★）に固定 | 自由に選べる（トレーニングと同じ部品） |
| 自己ベスト・称号 | 単元ごとに記録・更新 | **更新しない** |
| 記録 | 単元ごとの最高スコアなど | 直近20回の履歴（同じ条件で再挑戦できる） |

公式は、モード選択で「公式」を選んだときだけ成立します。カスタムで全カテゴリ・全難易度を選んでも、公式扱いにはなりません（内部で `mode: 'official' | 'custom'` を区別しています）。

#### 出題
- **公式タイムアタック**：難易度を決められた順に出します（`js/time-attack.js` の `OFFICIAL_DIFFICULTY_ORDER`）。1問目から順に **★ → ★★ → ★ → ★★ → ★★★ → ★ → ★★ → ★★★ → ★★★★ → ★★ → ★★★ → ★★★★**、13問目以降は **★★★ → ★★★★** のくり返しです（5問目は必ず★★★）。どの問題が出るかは、難易度ごとにシャッフルして順に出し、その難易度の問題を出し終えたら並べ直します（1巡の中では重複しません）。前半でテンポよく調子をつかみ、後半は難しい問題が続く流れにするためです。
- **カスタムタイムアタック**：選んだ条件の問題をシャッフルして出題し、**全部出し終えたら並べ直して続けます**（1巡の中では重複しません）。
- どちらも、直前と同じ問題が続かないようにしています（対象が1問だけのカスタムは除く）。
- 問題データ（`errorLine` など）は書き換えません。未検証の問題をその場で作ることもしません。

#### 得点（暫定。`js/time-attack.js` の `SCORE_RULES` で変更できます）

正解1問ごとに **単元ごとの基礎点 ＋ 連続正解ボーナス** が加算されます（公式・カスタムとも同じ。ご要望により、単元ごとの基礎点に変更しました）。

- **連続正解ボーナス**：連続 n 問目の正解で **10 × (n − 1) 点**（0, 10, 20, … と10点ずつ増え、**上限50点**＝連続6問目以降。ご要望により上限を100点から50点に変更）。
- **不正解**：**100点の減点**（ご要望により追加）。連続正解数を0に戻します（次の正解のボーナスは0点から）。スコアは0点より下にはしません（0点のときの不正解は0点のまま、100点未満のときは0点に）。プレイ中は「✖ ミス 1/3　−100」、結果画面の問題カードには「−100」と表示します。減点の大きさは `SCORE_RULES.missPenalty` で変えられます。

- 連続正解ボーナスの上限は `SCORE_RULES.maxBonus`（50点）で変えられます。

#### ゲームオーバー（`js/time-attack.js` の `CONFIG.maxMisses` で変更できます）

### 🎓 ティーチャー認定試験

単元ごとに5つの試験があり、順番に合格するとティーチャーランクが上がります。制限時間はなく、**ヒントは使えません**。回答はトレーニングと同じ「行を選ぶ → 添削する！」の2段階で、1問ごとに正誤と解説を確認できます。

#### 試験の一覧と出題配分（暫定。`js/certification.js` の `EXAMS` で変更できます）

| 試験 | 難易度 | 最大問題数 | 必要正解数 | 不合格になる不正解数 | ★ | ★★ | ★★★ | ★★★★ |
|---|---|---:|---:|---:|---:|---:|---:|---:|
| 第1試験 | ★のみ | 5 | 3 | 3 | 5 | 0 | 0 | 0 |
| 第2試験 | ★〜★★ | 6 | 4 | 3 | 3 | 3 | 0 | 0 |
| 第3試験 | ★〜★★★ | 7 | 5 | 3 | 2 | 2 | 3 | 0 |
| 第4試験 | ★〜★★★★ | 8 | 6 | 3 | 1 | 2 | 3 | 2 |
| 最終試験 | ★〜★★★★ | 10 | 10 | 1 | 1 | 2 | 3 | 4 |

#### 合格・不合格の判定
- 合格：`正解数 >= 必要正解数`
- 不合格：`不正解数 > 最大問題数 - 必要正解数`（残りを全部正解しても届かない）
- 試験中の画面上部には、1行目に「単元・試験名」、2行目に難易度の★と正解数（例：✔ 1/3＝合格に必要な3問のうち1問正解）を表示します。何問目かは、問題のバッジ（「第2問」など）で示します。
- **合否が決まった時点で試験は終わり、残りの問題は出題しません**（例：第1試験で最初の3問に正解したら、その時点で合格）。最後に答えた問題の解説は確認でき、そのあとのボタンは「結果を見る」に変わります。
- 「やめる」やブラウザの「戻る」で中断した試験は、合格扱いにせず、記録もしません（挑戦回数も、合否が決まった試験だけ数えます）。

#### 出題
- 試験ごとに、難易度別の必要数の問題を**最初にまとめて選び、ランダムな順番**で出題します（難易度順に固めません）。1回の試験で同じ問題は出ません。
- 難易度の中では、なるべくカテゴリが偏らないように選びます（それまでに選んだ数が少ないカテゴリから順に）。必要数を満たすことを優先します。
- 問題が足りない難易度があるときは、その試験を始められません（例：「★★★★の問題が3問不足しているため、現在この試験には挑戦できません。」）。低い難易度で埋めたり、同じ問題を重複させたりはしません。

#### ティーチャーランク（暫定。`js/certification.js` の `RANKS` で変更できます）

| 状態 | ランク | アイコン |
|---|---|---|
| 未認定 | ティーチャー見習い | 🔰 |
| 第1試験クリア | 新人ティーチャー | ✏️ |
| 第2試験クリア | 一人前ティーチャー | 📘 |
| 第3試験クリア | ベテランティーチャー | 🏅 |
| 第4試験クリア | エキスパートティーチャー | 🎖️ |
| 最終試験クリア | マスターティーチャー | 👑 |

- ランクは**いちばん上の合格済み試験**で決まり、単元ごとに独立しています（ある単元の合格で、別の単元の試験は解放されません）。ランクごとに色とアイコンがあります。
- **解放条件**：最初は第1試験だけ挑戦できます。合格すると次の試験が解放されます。合格済みの試験はいつでも再挑戦でき、再挑戦で不合格になってもランクは下がりません。
- 結果画面：合格なら「第3試験 合格！」、初めての合格では昇格の演出（「ベテランティーチャーに昇格！」「第4試験が解放されました！」）とランクアップのファンファーレ。最終試験に初めて合格すると、特別なファンファーレが鳴ります。不合格なら落ち着いた演出と、再挑戦をうながすコメントを表示します。ボタンは「次の試験へ」（合格して次がある場合）「もう一度挑戦」「認定試験一覧に戻る」「タイトルへ」です。

### 🏆 記録の保存と記録画面

記録はブラウザの `localStorage` に、キー `calcTeacher.records`（効果音の設定 `calcTeacher.sound` とは別）で保存します。保存データにはバージョン番号（`version: 1`）を付けています。

| 公式タイムアタック（単元ごと） | 最高スコア・達成日・最大連続正解数・プレイ回数・称号。**最後までプレイした公式の回だけ**が対象（カスタムや途中でやめた回は反映しない） |
| カスタムタイムアタック | 直近20回の履歴（日時・単元・カテゴリ・難易度・スコア・正解数・不正解数・最大連続正解数）。21件目からは古いものから消える |
| ティーチャー認定（単元ごと） | 最高クリア試験（＝ランク）・試験ごとの合格状況・挑戦回数・初合格日 |

記録画面（タイトルの「🏆 記録を見る」）には「公式タイムアタック」「カスタム履歴」「ティーチャー認定」の3つのタブがあります。公式タイムアタックのタブは単元ごとに称号と、その下に「ベストスコア」「最大連続」「プレイ回数」を同じ文字の大きさで横に並べて表示し（達成日は表示しません。保存・引継ぎはします）、ティーチャー認定のタブはランク・最高クリア・次に挑戦する試験を表示します（試験ごとの合格・挑戦回数の一覧は表示しません）。どちらのカードも、公式は最高記録3000点以上で金・2200点以上で銀・1500点以上で銅、認定は最終試験の合格で金・第4試験で銀・第3試験で銅になり、金は光ります。カスタム履歴からは「同じ設定で再挑戦」で同じ条件のカスタムタイムアタックをすぐに始められます。同じ履歴は、タイムアタックのモード選択画面の「カスタムタイムアタック」の下にある「📜 カスタムタイムアタックの履歴」からも見られます（直近20回）。

設定画面の「🗑 記録を消す」で、公式・カスタム・認定のすべての記録を消せます（「本当に消しますか？」で「はい」を選んだときだけ。効果音の設定は残ります。新しい版のアプリで保存された記録は消しません）。

**保存の安全対策**
- 保存データがない → 空の記録で始めます。
- 保存データが壊れている（JSON として読めない）→ 元の文字列を `calcTeacher.records.backup` に退避してから、空の記録で始めます。元のデータや効果音の設定は消しません。
- 古い版のデータ（バージョンがない・小さい）→ 足りない項目を補って読み込みます。新しい版のアプリが保存したデータ → 形式がわからないため、上書きしない（読み取り専用）にします。
- `localStorage` が使えない・容量がいっぱい → 保存に失敗しても例外を出さずにゲームを続け、結果画面に「記録を保存できませんでした」と表示します。

別の端末へ記録を移すには、引継ぎコードを使います（「第5段階」の節を参照）。

### 👦👧 生徒キャラクターとセリフ

プレイヤーを「先生」、登場するキャラクターを「答案を添削してもらう生徒」として、タイトル画面と各モードの結果画面で生徒が話しかけます。純粋な表示の演出で、問題データ・採点・得点・記録・ランク・効果音には影響しません（音声の読み上げもありません）。

- **キャラクター**：男の子（👦）と女の子（👧）。画像ではなく絵文字で表示し、横に角丸の吹き出し（しっぽ付き）でセリフを出します。軽いフェードインで現れます（`prefers-reduced-motion` では動きなし）。
- **タイトル画面**：先生のイラストの横に表示します。タイトル画面に入るたびに（設定や記録から戻ったときも）選び直します。セリフは10種類。「ぼく」を含むセリフは男の子だけ、「わたし」を含むセリフは女の子だけが話し、ほかは共通です。

### ヒント機能

- 問題画面の「💡 ヒント」で、JSON の `hint` を表示します。もう一度押すと閉じます。
- 問題の考え方を示すもので、最初に間違えた行を直接教えるものではありません。
- ヒントを見ても**減点はなく、正解率にも影響しません**。制限時間もありません。
- 次の問題に進むと、ヒントは閉じた状態に戻ります。

### 見やすさ・操作しやすさの工夫

- 答案はノート風の用紙に表示し、行ごとに高さ56px以上のタップ領域にしています（スマートフォン・iPad で押しやすい大きさ）。
- 正誤は色だけでなく、**記号と文字**でも示します（✔ 正解！／✖ キミの答え／✖ 最初のミス／👀 ここをもう一度確認しよう！／◎ 全部正しい）。不正解のときの「キミの答え」は点線の枠と斜線でも区別します。
- 横に長い式は、枠に収まるまで文字を少しずつ小さくします（最小70%）。それでも収まらないときは横スクロールにして、式が見切れないようにしています。フォントの読み込みや画面の回転で幅が変わったときも、調整し直します。
- 「○ 全部正しい！」と「添削する！」は答案のすぐ下に横並びで置き、行を選んだ流れのまま押せるようにしています。判定後は「添削する！」が同じ位置で赤い「次の問題へ」（最後の問題では「結果を見る」、解き直しでは「結果にもどる」）に変わるので、指を大きく動かさずに次へ進めます。「全部正しい！」は正解の印の表示に使います。
- 方程式以外（式の計算・式の値）では、2行目以降が「=」から始まるので、生徒の答案と「正しい計算過程」の1行目（問題の式）だけを全角スペース1文字分右にずらして、式の頭をそろえています（問題データは変更せず、表示だけで調整）。
- 方程式では、生徒の答案と「正しい計算過程」のそれぞれで、各行の「＝」の縦の位置をそろえています。各行を「左辺｜＝｜右辺」に分けて表示し、左辺の幅をいちばん長い左辺に合わせます。長い式は、まとまり全体を同じ倍率で縮めます（最小70%）。行を選んだときや採点後に枠の見た目が変わっても「＝」がずれないよう、枠の太さは変えずに内側の影で強調しています（問題データは変更せず、表示だけで調整）。
- iPad 横向き・PC（幅900px以上）では、答案を左、ヒント・解説を右に並べます。
- ダークモードと、アニメーションを減らす設定（`prefers-reduced-motion`）に対応しています。
- 解説の `$...$` の数式は KaTeX で表示し、それ以外の文字はすべてエスケープします。データの文字列が HTML やスクリプトとして解釈されることはありません。

## 出題・採点の仕組み

### 出題
- 問題は既存の `js/data-loader.js` で `data/manifest.json` と単元ごとの JSON から読み込みます（読み込み処理は新しく作っていません）。
- 選んだ条件に合う問題をシャッフル（Fisher–Yates）し、先頭から指定数を出題します。**1回のプレイで同じ問題は出ません。**
- 問題（ID）を選んだあと、別の乱数で答案パターン（正答25%・誤答75%。`js/question-variants.js`）を抽選し、その答案を出題します（第7段階）。1回のプレイの正答の数をそろえる補正はしません。JSON の `errorLine` も書き換えません。
- URL に `?seed=123` を付けると、出題順と答案パターンの乱数を固定できます（不具合の再現・テスト用。答案パターンの乱数は出題順とは別なので、出題順は第6段階までと同じです）。

### 採点
- プレイヤーが選んだ行の index が、**出題した答案パターン**の `errorLine` と同じなら正解。
- 「全部正しい！」を選び、出題した答案パターンの `errorLine` が `null`（正答パターン）なら正解。
- それ以外は不正解。
- 採点は**事前に検証済みの正解データとの比較だけ**で行い、プレイ中に数学的な検証はしません。
- ただし、出題前に問題ごとに最低限の整合性（`errorLine` が答案の範囲内か、必須項目があるか等）を確かめます。不整合のある問題は出題対象から除き、設定画面にその旨を表示します。万一、採点時に不整合が見つかった場合は、誤った採点をせずにエラー画面を表示します。

## 開発者用プレビュー

## 検証スクリプトがカバーする範囲と限界

### 自動で保証できること

| 項目 | 方法 |
|---|---|
| JSON の書式、必須項目、型、ID の重複、値の範囲、行数 | 構造チェック |
| 数式が KaTeX で表示できること | KaTeX 0.16.47 で実際に描画する（`strict: "error"`） |
| 式の計算で、となりの行どうしが等しいかどうか | 無作為に選んだ有理数8点で両辺の値を比べる。計算は BigInt を使った**厳密な分数計算**で、誤差はない |
| 式の値の問題 | `substitution` の値を代入して、各行の値を比べる |
| 方程式で、となりの行どうしの解が同じかどうか | 1次方程式の解集合（解1つ／すべての数／解なし）を求めて比べる |
| 「最初に間違えた行」の整合性 | 指定行より前はすべて等価、指定行は等価でない、指定行より後はすべて等価（＝ほかに独立した誤りがない） |
| 正しい答案・正しい計算過程に誤りがないこと | すべての行が等価で、最終行が正しい答えと一致する |

現在の結果（800問）：**ERROR 0 件 / WARN 0 件**。中1の300問のうち271問と、中2・中3の500問すべては、自動で数学的整合性を確認済みです。中1の29問は手動確認項目があり、AI が確認済みです（「文字式の表し方」25問と、途中式が正しい計算過程と異なる別解の答案など）。

第6段階で、平方根（厳密な計算）・2次方程式（解の集合）・連立方程式（元の連立方程式の解で各行を確かめる）・答えの形（整理・展開・因数分解・根号の簡単化・有理化・約分）を自動で検証できるようにしました（「第6段階」の節）。

### 自動では保証できないこと（＝手動確認が必要）

- **数学的に等価でも、誤りになる場合**：「行どうしが等価」だけでは、表記ルールの誤り（例：`a\times3` を `a3` と書く）は見つけられません。そのため「文字式の表し方」の問題は、必ず手動確認の対象にしています。
- **別解の妥当性**：全部正しい答案の途中式が `correctSolution` と違う場合は、手動確認の対象にしています。
- **解説・ヒントの内容、誤答の自然さ、難易度の妥当性**：文章や教育上の判断なので、人が確認します。
- **確率的な判定であること**：式の等価性は8点での一致で判定しています。中学で扱う次数の低い式では事実上確実ですが、厳密な証明ではありません。
- **対応していない記法**：累乗根（`\sqrt[3]{}`）、3次以上の方程式、3つ以上の文字の連立方程式、解が1組に決まらない連立方程式、1つの方程式に2種類以上の文字がある問題（連立方程式を除く）は解析しません。そのような行は「判定不能（`?`）」となり、**自動では合格扱いにせず** MANUAL として表示します。
- **答えの形**：中1の3単元では、最終行に × ÷ が残っている場合だけ MANUAL にしています（中1の判定結果を変えないため、第6段階の「答えの形」の検証は当てはめていません）。中2・中3の式の計算でも、分数の係数が約分されているか（`\frac{3}{6}a` など）までは見ていません（平方根・2次方程式の答えの約分は確かめます）。
- **連立方程式の途中の行**：「その行の式が元の連立方程式の解で成り立つか」で判定するので、解で成り立つが答案の流れとして不自然な行（関係のない正しい式）は見つけられません。答案の自然さは人が確認します。

### 手動レビューの記録

手動確認は、`review/manual-review.json` に問題ごとに記録しています（確認者、日付、確認項目、メモ、**問題内容の SHA-256 ハッシュ**）。
レビュー後に問題を変更するとハッシュが合わなくなり、「要再レビュー」と表示されます（`npm test` ではエラー）。

800問は、Claude Code（AI）が全問を確認して記録しました。**数学講師による確認はまだ行っていません。実際に授業で使う前に、数学の先生による確認をおすすめします。**
先生が確認したら、`node tools/review-stamp.js --reviewer "先生の名前" --role teacher ID ...` で記録できます（`--all` は、内容が変わっていない既存の記録をスキップします）。集計スクリプトでは、AI の確認と数学講師の確認を分けて数えます。

### 第5段階の判断記録

| 判断が必要だった点 | 決めたこと | 理由 |
|---|---|---|
| コードの短くし方 | 独自のバイト列（項目名なし・可変長整数・単元番号・日時の差）＋ Base64URL。圧縮ライブラリは使わない | 中1の3単元で約140文字と十分短く、ライブラリなしでどのブラウザでも同じ結果になるため（JSON のままでは約1,700文字） |

| クリア状況 | 「第1〜最高クリア試験はクリア済み」として入れず、まだクリアしていない「次の試験」の挑戦回数だけを別に入れる | 試験は順番にしか挑戦できないので、最高クリア試験から一意に決まるため |
| 単元の表し方 | 固定の番号表（並べかえ・削除をしない）＋番号表にない単元は文字のまま | 中2・中3の単元を追加しても、古いコード・新しいコードを別の単元として読まないため |
| 知らない単元番号 | 「アプリを更新してから」のメッセージで拒否 | 新しいアプリの番号表でつくられたコードなので、どの単元か分からないまま保存しないため |
| 変わった記録のコード化 | アプリが普通につくらない記録（クリアしたのに挑戦回数0 など）は、コードにするときにそろえる | どんな記録からつくったコードでも、読み込みの検証に必ず通るようにするため |
| 保存できない環境 | localStorage が使えない端末では、引継ぎを失敗として扱う | メモリ上だけで成功にすると、再読み込みで記録が消えて「引き継げた」と誤解されるため |

| ファイルの分け方 | `time-attack.js`・`certification.js`・`records.js` を追加し、画面は `app.js` に置いた | 指示書23章のとおり。ルールと画面を分け、ルール側は Node で自動テストできるようにするため |
| 認定試験の進行 | `TrainingSession` を拡張した `CertificationSession` で、トレーニングの添削画面・解説をそのまま使う | 「行を選ぶ→添削する！」・解説・数式の整列などを二重に作らないため |
| タイムアタックの正誤の音 | 既存の正解音・不正解音を短くした版（約0.17秒）を追加 | 約0.3秒ごとに次の問題が出るため、0.5秒前後の音では重なって騒がしくなる（指示書21章） |
| 公式の初回の扱い | 初めての公式記録は「初めての公式記録！」と表示し、自己ベスト更新の効果音は2回目以降に上回ったときだけ鳴らす | 初回は比べる記録がないため |
| 0点の公式の回 | 最後までプレイすれば、0点でも公式記録（プレイ回数）に数える | 「完走記録のみ」の条件を満たしているため |
| 途中でやめたときの戻り先 | タイムアタックは設定画面、認定試験は試験一覧、トレーニングはタイトル | それぞれ、すぐ再挑戦しやすい画面にするため |
| 結果画面の解説 | 問題をタップすると解説のポップアップ（生徒の答案に「キミの答え」「最初のミス」の印・解説・正しい計算過程） | 指示書7章・14章。スマホ縦でも回転させずに読める形にした |
| カウントダウンの間隔 | 3・2・1 を0.8秒ずつ、そのあと START! | テンポよく始めるため |
| 壊れた記録データ | 元の文字列を `calcTeacher.records.backup` に退避してから空で始める。新しい版のデータは読み取り専用 | 「他の保存設定や記録を不用意に削除しない」（指示書20章） |
| テストの件数 | ロジック・UI テストの期待値を、数値ではなく問題データから数える形に変更 | 問題を追加するたびにテストが壊れないようにするため |

### 第2段階の判断記録

| 判断が必要だった点 | 決めたこと | 理由 |
|---|---|---|
| 添削結果を別画面にするか | 問題画面の下（幅900px以上では右側）に結果パネルとして表示 | 答案と解説を見比べながら「どの行がなぜ誤りか」を確かめられるようにするため。iPad 横向きでは左右に並ぶ |
| 単元は複数選べるか | 1つだけ | 指示書の「以下から選択」に合わせた。`game.js` は単元を引数で受け取るので、将来の複数単元にも拡張しやすい |
| 難易度の一括選択 | 「おまかせ」はやめ、「すべて選択」ボタンを置く。全難易度が選ばれているときだけ「すべて解除」に変わる。個別の ★ は押すたびに選択・解除 | 操作の意味をはっきりさせるため（ご要望により変更） |
| カテゴリの件数表示 | カテゴリ・難易度のボタンに出す「○問」は単元全体での数。実際に出題できる数は、設定画面の下とスライダーで示す | 互いの選択で数や選べる範囲が変わると、選んでいた難易度が勝手に外れるなど操作がわかりにくくなるため |
| 問題数の選び方 | 5問・10問・すべての3択をやめ、スライダーで1問〜最大数を選ぶ。最大数を超えて選んだ数は覚えておき、条件を変えて最大数が増えたら元の数に戻る | 少ない問題数でも気軽に練習できるようにするため（ご要望により変更） |
| 行番号の表示 | 1行目＝問題の式（選べない）、2行目以降を選択。画面の「○行目」は index＋1 | 指示書の表示例（1行目 3x+5=11 …）に合わせた |
| やめる確認 | ブラウザ標準の `confirm()` ではなく、画面内のダイアログ（`<dialog>`） | iPad でも見た目がそろい、自動テストもできるため |
| ブラウザの「戻る」 | プレイ中は確認ダイアログを出し、「つづける」なら進行状態をそのまま保つ | 意図しない画面遷移で進行状態が壊れないようにするため |
| 出題順の乱数 | 通常は `Math.random`。`?seed=` で固定できる | 不具合の再現と自動テストのため |
| データ不整合への対応 | 出題前に問題ごとに確認し、不整合な問題は出題から除外して設定画面に表示。採点時に見つかればエラー画面 | 「誤採点したまま進めない」（指示書5章） |

### 第1段階の仕様の判断記録

|---|---|---|---|

## 今後の実装予定

### 第7段階以降（アプリ）
- **実機での確認**：自動テストはヘッドレスブラウザで行いました。iPad・iPhone の Safari、Android の Chrome での操作感・効果音・タイムアタックの時間の感じ方は、授業で使う端末で確かめてください。
- **得点・称号・試験の基準の再調整**：今の値は暫定です。問題を増やし、生徒のプレイ速度を見てから、`SCORE_RULES`・`TITLES`・`EXAMS`・`RANKS` を見直します。
- **公式記録のルールの版**：公式タイムアタックの難易度の出題順を変えたため、それ以前の自己ベスト（全難易度をシャッフルして出していたころの記録）と、これからの記録は、出題の条件が同じではありません。記録は消さずにそのまま比べています。今後も公式のルールを変える場合は、記録に「ルールの版」を持たせて、版ごとに自己ベストを分けることを検討します。
- ランキング、BGM、QR コードでの引継ぎ（今の引継ぎコードの文字列をそのまま QR コードにできます）
- 間違いの種類別の成績分析（各問題の `errorType` と、各モードの採点結果を使える）
- カテゴリ選択の再利用（実装済みの方針）：出題条件は `{ unit, categories, difficulties }` という、画面やモードに依存しない形にしています。`js/game.js` の `filterPool`（絞り込み）と `listCategories`（カテゴリ一覧）は、タイムアタックでもそのまま使えます。
  - 生徒が選んだ条件を使うモード（トレーニング・タイムアタック）：設定画面で選んだ条件（`js/app.js` の `selectedCriteria()`）を渡します。
  - 試験側が条件を決めるモード（認定試験）：試験の種類ごとに `{ unit, categories, difficulties }` を用意して渡します。`categories` や `difficulties` を省略すると「すべて」になります。
