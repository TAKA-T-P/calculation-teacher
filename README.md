# 計算ティーチャー！

中学生向けの計算学習アプリです。生徒が数学の先生役になり、別の生徒が解いた答案から「**最初に間違えた行**」を見つけます。
正誤を当てるだけでなく、途中式を読み解きながら正しい計算規則を身につけることをねらいとしています。

このリポジトリは **第1段階（問題データの設計・作成・検証）** の成果物です。ゲーム画面はまだありません。

---

## すぐに試す

Node.js 18 以上が必要です（開発時は v24 で確認）。

```bash
npm install          # KaTeX（検証スクリプト用）をインストール
npm test             # 検証ライブラリの自己テスト + 異常系テスト + 全問題の検証
npm run serve        # プレビュー画面 → http://localhost:8080/
```

ポート 8080 が使用中の場合は、`npm run serve -- 8081` のように別のポートを指定してください。
プレビュー画面は `fetch` で JSON を読むため、`index.html` をダブルクリックで開く（file://）方法では動きません。GitHub Pages にそのまま置けば動きます。

## コマンド一覧

| コマンド | 内容 |
|---|---|
| `npm run validate` | 全問題を検証（ERROR があれば終了コード 1） |
| `npm run validate:verbose` | 各行の判定（`≡` / `≠` / `?`）や、正しい答え・解も表示 |
| `npm run validate:strict` | 手動レビューが記録されていない問題や、レビュー後に変更された問題もエラーにする |
| `npm test` | 自己テスト・異常系テスト・strict 検証をまとめて実行 |
| `npm run review:list` | 手動レビューの状況を一覧表示 |
| `node tools/review-stamp.js --reviewer "名前" [--note "メモ"] ID ...` | 手動レビュー済みとして記録（`--all` で全問） |
| `npm run serve` | プレビュー用の簡易サーバー |

### 2. 問題データ仕様

[docs/question-data-spec.md](docs/question-data-spec.md) にまとめました。指示書の標準仕様に加えて、`instruction`・`substitution`・`verification` の3つを任意項目として追加しています（理由は下の「仕様の判断記録」を参照）。

### 3. 自動検証スクリプト

`tools/validate-questions.js` が、指示書の「自動検証の要件」をすべてチェックします。さらに、自作の検証ライブラリ（`js/lib/math-verify.js`）で各行の数学的な等価性を判定します。

**現在の結果（30問）：ERROR 0 件 / WARN 0 件**
- 27問：誤り行の位置、誤り行の前後の整合性、正しい計算過程を、自動で数学的に確認済み
- 3問：自動確認に加えて、手動確認が必要な項目あり（下記）。手動確認は完了済み
- 21問の誤答すべてで、「直前の行と最初に等価でなくなる行」がデータの `errorLine` と一致
- 30問すべての手動レビューを記録済み（`review/manual-review.json`）

### 4. プレビュー画面

`index.html` で、次のことができます。
- 単元・答案の種類（誤りあり／全部正しい）・難易度で絞り込み
- 問題IDのチップ、または ← → キーで問題を切り替え
- 指示文、元の問題、生徒の答案（行番号と index）の表示
- 「正解・解説を表示」の切り替え（<kbd>A</kbd> キー、または URL に `?reveal=1`）
  - 最初に間違えた行の強調表示、「全部正しい！」の判定、誤りの種類、解説、正しい計算過程
  - 開発者向けに、各行の自動検証結果（`≡` / `≠` / `?`）と手動レビューの状況
- ヒントの表示（<kbd>H</kbd> キー）
- URL の `#J1-EQ-0003` で特定の問題を直接開く

データは毎回キャッシュを使わずに読み込むので、JSON を編集してページを再読み込みすれば反映されます。

## 検証スクリプトがカバーする範囲と限界

### 自動で保証できること

| 項目 | 方法 |
|---|---|
| JSON の書式、必須項目、型、ID の重複、値の範囲、行数 | 構造チェック |
| 数式が KaTeX で表示できること | KaTeX 0.16.47 で実際に描画する（`strict: "error"`） |
| 式の計算で、となりの行どうしが等しいかどうか | 無作為に選んだ有理数8点で両辺の値を比べる。計算は BigInt を使った**厳密な分数計算**で、誤差はない |
| 式の値の問題 | `substitution` の値を代入して、各行の値を比べる |
| 方程式で、となりの行どうしの解が同じかどうか | 1次方程式の解集合（解1つ／すべての数／解なし）を求めて比べる |
| 「最初に間違えた行」の整合性 | 指定行より前はすべて等価、指定行は等価でない、指定行より後はすべて等価（＝ほかに独立した誤りがない） |
| 正しい答案・正しい計算過程に誤りがないこと | すべての行が等価で、最終行が正しい答えと一致する |

検証ライブラリが正しく計算できることは `tools/selftest-math-verify.js` で、検証スクリプトが誤りを見のがさないことは `tools/test-validator.js` で確かめています（19 項目の異常系テスト。壊したデータを使います）。

### 自動では保証できないこと（＝手動確認が必要）

- **数学的に等価でも、誤りになる場合**：「行どうしが等価」だけでは、表記ルールの誤り（例：`a\times3` を `a3` と書く）は見つけられません。そのため「文字式の表し方」の問題は、必ず手動確認の対象にしています。
- **別解の妥当性**：全部正しい答案の途中式が `correctSolution` と違う場合は、手動確認の対象にしています（PN-0010、EQ-0003）。
- **解説・ヒントの内容**：解説が実際の誤りを正しく説明しているか、ヒントが正確かは、文章なので自動では判定できません。全問を手動で確認しています。
- **誤答の自然さ・難易度の妥当性**：教育上の判断なので、人が確認します。
- **確率的な判定であること**：式の等価性は8点での一致で判定しています。中学で扱う次数の低い式では事実上確実ですが、厳密な証明ではありません。
- **対応していない記法・単元**：`\sqrt`、2次以上の方程式、連立方程式、2種類以上の文字を含む方程式は、現在は解析しません。そのような行は「判定不能（`?`）」となり、**自動では合格扱いにせず** MANUAL として表示します。第2段階以降で対応が必要です（下記）。
- **答えの形（約分・整理）**：最終行に × ÷ が残っている場合だけ MANUAL にしています。約分し忘れなどは、手動確認で見ています。

### 手動レビューの記録

手動確認は、`review/manual-review.json` に問題ごとに記録しています（確認者、日付、確認項目、メモ、**問題内容の SHA-256 ハッシュ**）。
レビュー後に問題を変更するとハッシュが合わなくなり、検証スクリプトが「要再レビュー」と表示します（`npm test` ではエラー）。

今回の30問は、Claude Code（AI）が全問を確認して記録しました。**実際に授業で使う前に、数学の先生による確認をおすすめします。**
先生が確認したら、`node tools/review-stamp.js --reviewer "先生の名前" --all` を実行すると、確認者を上書きして記録できます。
ただし `--all` は、内容が変わっていない既存の記録をスキップします。全問を上書きしたい場合は、ID を並べて指定してください。

## 仕様の判断記録

指示書で決まっていなかった点について、確定済みの事項を優先して、次のように決めました。

| # | 判断が必要だった点 | 決めたこと | 理由 |
|---|---|---|---|
| 1 | 単元ファイルの形式 | `{ schemaVersion, grade, unit, questions: [...] }` の形にした | 将来、項目を追加したときに版を区別できるようにするため |
| 2 | 単元ファイルの一覧 | `data/manifest.json` を追加した | ファイル名を画面のプログラムに書かずに、単元を追加できるようにするため |
| 3 | 式の計算の2行目以降の書き方 | `=` で始める（`"=-5+8-6"`） | 参考PDFの書き方に合わせた。1行目（問題）と区別でき、1行1式になる |
| 4 | `errorLine` に 0 を指定できるか | 指定できない（1 以上） | 1行目は問題を再掲した行で、添削の対象ではないため（指示書 3-1） |
| 5 | 「式の値」の問題で、代入する値をどこに書くか | 任意項目 `instruction`（表示用）と `substitution`（検証用）を追加した | 問題式だけでは代入する値がわからず、自動検証もできないため |
| 6 | 自動検証できない問題の扱い | 任意項目 `verification: {mode:"manual"}` で明示できるようにした。解析できない行も自動で MANUAL にする | 「自動的に合格扱いしない」（指示書 7章）を守るため |
| 7 | 手動確認の完了をどう示すか | 内容のハッシュ付きのレビュー記録にした | 完了条件「手動検査が完了している」を確認でき、問題を変更したら再レビューが必要なことがわかるようにするため |
| 8 | 説明文の中の数式 | `$...$` で書く | KaTeX で表示でき、自動検証でも構文を確認できるため |
| 9 | 解説の中で行番号を使うか | 使わず、式そのもので誤りの箇所を示す | `errorLine`（0始まり）と画面の「〇行目」（1始まり）の取り違えを防ぐため |
| 10 | 「全部正しい」の割合 | 各単元3問・全体30%にした | 指示書の「各単元2〜3問」「全体20〜30%」の範囲内。別解の答案（★★★★）を入れるために、上限の3問にした |
| 11 | 文字式の1次式の減法（かっこの前の負号）の分類 | 「分配法則など」に分類した | かっこをはずす操作が中心になるため（docs/pdf-analysis.md 参照） |
| 12 | 方程式の PDF にある「比例式」 | 第1段階では扱わない | 指示書の方程式のカテゴリ（移項・かっこ・小数・分数）にないため |
| 13 | 演算の優先順位（自動検証） | 暗黙のかけ算（`3y`、`2(x+1)`）を `\times` `\div` より先に計算する | 日本の中学校の慣習（`x\div3y = \frac{x}{3y}`）に合わせた。読み方が分かれる式は使わないことを仕様書に明記 |
| 14 | KaTeX のバージョン | 0.16.47 に固定（CDN・npm とも） | 既知の脆弱性を修正した 0.16 系の版。`npm audit` に残る1件（GHSA-238p-pmpm-9mq7）は「すでにプロトタイプ汚染が起きている場合」に限られ、自分たちのデータだけを表示する本アプリへの影響は小さいと判断した。0.19 系への更新は互換性の確認後に行う |

## 今後の課題

### 問題データ
- **誤り行の位置にかたよりがある**：誤答21問のうち14問は2行目（index 1）が誤りです。ゲームで「2行目を選べば当たりやすい」と覚えられないよう、問題を増やすときは3行目以降に誤りがある答案を増やします。
- 方程式の★1が1問だけなので、★1の問題を増やします。
- 中2・中3の5単元の問題データを作り、単元ごとにカテゴリを決めます。
- 1つの単元で同じ誤りの種類がかたよらないよう、問題を増やすときに検証スクリプトの集計を参考にします。
- 実際に授業で使う前に、数学の先生にレビューしてもらいます。

### 検証スクリプト
- 平方根（`\sqrt`）への対応：根号を含む式の等価性を判定できるようにする（数を代入する方法、または根号の形の整理）
- 連立方程式（2つの文字の解の組）、2次方程式（解が2つ）への対応
- 文字式の表記ルール（× の省略、係数の位置、`1a`・`-1a` の禁止など）を、ある程度自動でチェックする
- 答えの形（約分できるのにしていない、など）の自動チェック

### アプリ（第2段階以降）
- タイトル画面、トレーニングモード（ヒントあり）、60秒タイムアタック、ティーチャー認定試験
- 得点・称号・段位、成績の保存、引継ぎコード、効果音・BGM
- `js/data-loader.js` と `js/lib/` はゲーム画面からそのまま使えます。答案の行を選ぶ画面は、プレビュー画面の行の表示を元に作れます。

### 開発環境
- `index.html` は CDN（jsDelivr）から KaTeX を読み込んでいます。オフラインの教室でも使えるようにする場合は、KaTeX をリポジトリに入れる必要があります。
- 参考資料の PDF（`問題サンプル/`）は公開しない方針のため、`.gitignore` でリポジトリから除外しています。手元で PDF を参照する場合は、ローカルの `問題サンプル/` フォルダに置いてください。
