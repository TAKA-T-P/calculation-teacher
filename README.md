# 計算ティーチャー！

> キミは計算ミスを見抜けるか！？

中学生向けの計算学習ゲームです。生徒が数学の先生になって、別の生徒が解いた答案から「**最初に間違えた行**」を見つけ、添削します。
正誤を当てるだけでなく、途中式を読み解きながら正しい計算規則を身につけることをねらいとしています。

| 段階 | 内容 | 状態 |
|---|---|---|
| 第1段階 | 問題データの設計・作成・検証（中1・30問）、開発者用プレビュー | 完了 |
| **第2段階** | **タイトル画面・トレーニングモード（ゲーム画面）** | **完了** |
| 第3段階以降 | タイムアタック、ティーチャー認定試験、称号・成績保存など | 予定 |

---

## すぐに試す

Node.js 18 以上が必要です（開発時は v24 で確認）。

```bash
npm install          # KaTeX（検証スクリプト用）をインストール
npm run serve        # → http://localhost:8080/ でゲーム画面が開く
npm test             # 自動テスト一式（ブラウザ不要）
npm run test:ui      # ゲーム画面の操作テスト（Chrome または Edge が必要）
```

- ポート 8080 が使用中の場合は、`npm run serve -- 8081` のように別のポートを指定してください。
- 画面は `fetch` で JSON を読むため、`index.html` をダブルクリックで開く（file://）方法では動きません。GitHub Pages にそのまま置けば動きます（サーバーやデータベースは不要）。

| URL | 画面 | 対象 |
|---|---|---|
| `/`（`index.html`） | ゲーム画面 | 生徒 |
| `/preview.html` | 問題プレビュー | 開発者（生徒向け画面にリンクはありません。URL を直接入力するか、裏ワザで開きます） |

## 遊び方

1. **タイトル画面**で「トレーニング」を押します（「あそびかた」で説明も見られます）。
2. **設定画面**で、単元・難易度・問題数を選んで「添削スタート！」を押します。
3. **添削問題画面**で答案を上から読み、**最初に**計算を間違えた行をタップします。ミスがなければ「○ 全部正しい！」を選びます。
4. 「**添削する！**」を押すと答え合わせです。正解・不正解と、解説・正しい計算過程が表示されます。
5. 答え合わせのあと、「添削する！」ボタンが同じ位置で赤い「**次の問題へ**」ボタンに変わります。全問解き終わると（最後は「結果を見る」）**トレーニング結果**（正解率・出題数・正解数・まちがい数・ひとこと評価）が表示されます。
6. 結果画面の問題カード（1問目・2問目…）をタップすると、**その問題だけをもう一度解けます**。解き終わったら「結果にもどる」で結果画面に戻ります。

「最終的な答えが間違っている行」ではなく、「**最初に計算規則を誤った行**」を探すゲームです。

### 画面構成と画面遷移

```text
タイトル ─┬─ あそびかた ──────────────┐
          └─ トレーニング設定 ←────────┤
                │ 添削スタート！         │
                ▼                        │
             添削問題 ⇄ 添削結果（1問ごと）│
                │ 全問終了               │
                ▼                        │
             トレーニング結果 ── もう一度チャレンジ（同じ条件・新しい問題順）
                                 単元選択に戻る／タイトルへ
```

| 画面 | 主な表示・操作 |
|---|---|
| ① タイトル | タイトル・サブタイトル・先生をイメージしたイラスト、「トレーニング」「あそびかた」。タイムアタック・認定試験は押せない「準備中」の表示だけ。最下部に小さく「©2026 T.TAKEMOTO / KEC Glows」 |
| ② トレーニング設定 | 単元（`data/manifest.json` から自動で一覧化）、難易度（複数選択・おまかせ）、問題数（5問・10問・すべて）、出題できる問題数 |
| ③ 添削問題 | 上部に単元・難易度・問題番号（例 2/5）・正解数。指示文・問題・生徒の答案。答案の2行目以降はそれぞれ大きなタップ領域 |
| ④ 添削結果 | 問題画面の下（iPad 横・PC では右側）に表示。正解なら「添削成功！」とスタンプの演出、不正解なら「✖ 添削失敗…」と、キミの答え・最初の誤り行・まちがいの理由・正しい計算過程 |
| ⑤ トレーニング結果 | 正解率、出題数・正解数・まちがい数、評価コメント、問題ごとの ✔／✖ カード。カードをタップするとその問題を1問だけ解き直せる（元の正解率は変わらず、カードに「もう一度：✔ 正解」などと表示） |

### 単元・難易度・問題数の選び方

- **単元**：1つ選びます。中2・中3の単元は、データを追加して `data/manifest.json` に1行足すと、自動で一覧に出ます。
- **難易度**：★〜★★★★をいくつでも選べます。「おまかせ」はすべての難易度です。
  - 「おまかせ」の状態で ★ を1つ押すと、その難易度だけになります。そこから押すたびに追加・解除されます。
  - 選んだ単元に問題がない難易度は、押せない表示になります。
  - 難易度を1つも選んでいないときは、開始できません。
- **問題数**：5問（初期値）・10問・すべて。
  - 条件に合う問題が指定数より少ないときは、「条件に合う問題が○問なので、○問すべてを出題します」と表示し、ある分だけ出題します。同じ問題をくり返して数を埋めることはしません。
  - 出題できる問題が0問のときは「添削スタート！」を押せません。

### 操作のルール

- 答案の **1行目は問題の式の再掲**なので、選べません（ボタンの枠がなく、少し薄い色で表示）。選べるのは2行目以降です。
- 行は1つだけ選べます。別の行を押すと選び直し、同じ行をもう一度押すと解除です。
- 行を選ぶと「全部正しい！」の選択は解除され、「全部正しい！」を選ぶと行の選択は解除されます。
- 誤操作を防ぐため、行をタップしただけでは判定しません。**選んでから「添削する！」を押す2段階操作**です。何も選んでいないときは「添削する！」を押せません。
- 1問につき判定は1回だけです。判定後は答案の行もボタンも押せなくなります。
- 「やめる」ボタンやブラウザの「戻る」を押すと確認ダイアログが出ます。「やめる」を選ぶとタイトルに戻ります（途中経過は保存しません）。「つづける」なら、選択状態もそのまま続けられます。

### 生徒の答案と並べて表示

- 答え合わせのあと、「正しい計算過程」の下の「⇆ 生徒の答案と並べて表示」を押すと、ポップアップが開きます。
- 「行番号｜生徒の答案｜正しい計算過程」の3列で、**同じ行どうしを横に並べて**表示します。生徒の答案の最初の誤り行には「✖ 最初のミス」の印が付きます。方程式では、列ごとに「＝」の位置をそろえます。
- **スマートフォンの縦画面**では、ポップアップを右に90°回転して表示します（端末を横向きに持つと読みやすい向き）。横に並べるための幅を確保するためです。iPad やパソコン、スマートフォンの横画面では回転しません。
- 「閉じる」ボタン（または Esc キー、ブラウザの「戻る」）で閉じます。

### ヒント機能

- 問題画面の「💡 ヒント」で、JSON の `hint` を表示します。もう一度押すと閉じます。
- 問題の考え方を示すもので、最初に間違えた行を直接教えるものではありません。
- ヒントを見ても**減点はなく、正解率にも影響しません**。制限時間もありません。
- 次の問題に進むと、ヒントは閉じた状態に戻ります。

### 見やすさ・操作しやすさの工夫

- 答案はノート風の用紙に表示し、行ごとに高さ56px以上のタップ領域にしています（スマートフォン・iPad で押しやすい大きさ）。
- 正誤は色だけでなく、**記号と文字**でも示します（✔ 正解！／✖ キミの答え／✖ 最初のミス／👀 ここをもう一度確認しよう！／◎ 全部正しい）。不正解のときの「キミの答え」は点線の枠と斜線でも区別します。
- 横に長い式は、枠に収まるまで文字を少しずつ小さくします（最小70%）。それでも収まらないときは横スクロールにして、式が見切れないようにしています。フォントの読み込みや画面の回転で幅が変わったときも、調整し直します。
- 「○ 全部正しい！」と「添削する！」は答案のすぐ下に横並びで置き、行を選んだ流れのまま押せるようにしています。判定後は「添削する！」が同じ位置で赤い「次の問題へ」（最後の問題では「結果を見る」、解き直しでは「結果にもどる」）に変わるので、指を大きく動かさずに次へ進めます。「全部正しい！」は正解の印の表示に使います。
- 方程式以外（式の計算・式の値）では、2行目以降が「=」から始まるので、生徒の答案と「正しい計算過程」の1行目（問題の式）だけを全角スペース1文字分右にずらして、式の頭をそろえています（問題データは変更せず、表示だけで調整）。
- 方程式では、生徒の答案と「正しい計算過程」のそれぞれで、各行の「＝」の縦の位置をそろえています。各行を「左辺｜＝｜右辺」に分けて表示し、左辺の幅をいちばん長い左辺に合わせます。長い式は、まとまり全体を同じ倍率で縮めます（最小70%）。行を選んだときや採点後に枠の見た目が変わっても「＝」がずれないよう、枠の太さは変えずに内側の影で強調しています（問題データは変更せず、表示だけで調整）。
- iPad 横向き・PC（幅900px以上）では、答案を左、ヒント・解説を右に並べます。
- ダークモードと、アニメーションを減らす設定（`prefers-reduced-motion`）に対応しています。
- 解説の `$...$` の数式は KaTeX で表示し、それ以外の文字はすべてエスケープします。データの文字列が HTML やスクリプトとして解釈されることはありません。

## 出題・採点の仕組み

### 出題
- 問題は既存の `js/data-loader.js` で `data/manifest.json` と単元ごとの JSON から読み込みます（読み込み処理は新しく作っていません）。
- 選んだ条件に合う問題をシャッフル（Fisher–Yates）し、先頭から指定数を出題します。**1回のプレイで同じ問題は出ません。**
- 「全部正しい！」の割合や誤り行の位置を、ゲーム側で補正することはしません。JSON の `errorLine` も書き換えません（現行データは誤り行が2行目に多い傾向がありますが、問題を増やす段階で対応する方針です）。
- URL に `?seed=123` を付けると、出題順の乱数を固定できます（不具合の再現・テスト用）。

### 採点
- プレイヤーが選んだ行の index が `errorLine` と同じなら正解。
- 「全部正しい！」を選び、`errorLine` が `null` なら正解。
- それ以外は不正解。
- 採点は**事前に検証済みの正解データとの比較だけ**で行い、プレイ中に数学的な検証はしません。
- ただし、出題前に問題ごとに最低限の整合性（`errorLine` が答案の範囲内か、必須項目があるか等）を確かめます。不整合のある問題は出題対象から除き、設定画面にその旨を表示します。万一、採点時に不整合が見つかった場合は、誤った採点をせずにエラー画面を表示します。

### プログラムの役割分担

| ファイル | 役割 |

## 開発者用プレビュー

`npm run serve` を実行して、`http://localhost:8080/preview.html` を開きます（第1段階の `index.html` から移設しました。機能は同じです）。

**裏ワザ**：ゲームのタイトル画面の最下部にある「T.TAKEMOTO」を、3秒以内に5回タップすると開発者用プレビューが開きます（タブレットなどで URL を入力しにくいとき用）。

- 単元・答案の種類（誤りあり／全部正しい）・難易度で絞り込み
- 問題IDのチップ、または ← → キーで問題を切り替え
- 「正解・解説を表示」（<kbd>A</kbd> キー、または URL に `?reveal=1`）：誤り行の強調、解説、正しい計算過程、各行の自動検証結果（`≡` / `≠` / `?`）、手動レビューの状況
- ヒントの表示（<kbd>H</kbd> キー）
- URL の `#J1-EQ-0003` で特定の問題を直接開く

データは毎回キャッシュを使わずに読み込むので、JSON を編集してページを再読み込みすれば反映されます。

## 検証スクリプトがカバーする範囲と限界

### 自動で保証できること

| 項目 | 方法 |
|---|---|
| JSON の書式、必須項目、型、ID の重複、値の範囲、行数 | 構造チェック |
| 数式が KaTeX で表示できること | KaTeX 0.16.47 で実際に描画する（`strict: "error"`） |
| 式の計算で、となりの行どうしが等しいかどうか | 無作為に選んだ有理数8点で両辺の値を比べる。計算は BigInt を使った**厳密な分数計算**で、誤差はない |
| 式の値の問題 | `substitution` の値を代入して、各行の値を比べる |
| 方程式で、となりの行どうしの解が同じかどうか | 1次方程式の解集合（解1つ／すべての数／解なし）を求めて比べる |
| 「最初に間違えた行」の整合性 | 指定行より前はすべて等価、指定行は等価でない、指定行より後はすべて等価（＝ほかに独立した誤りがない） |
| 正しい答案・正しい計算過程に誤りがないこと | すべての行が等価で、最終行が正しい答えと一致する |

現在の結果（30問）：**ERROR 0 件 / WARN 0 件**。27問は自動で数学的整合性を確認済み、3問（PN-0010・EX-0001・EQ-0003）は手動確認項目があり、確認済みです。

### 自動では保証できないこと（＝手動確認が必要）

- **数学的に等価でも、誤りになる場合**：「行どうしが等価」だけでは、表記ルールの誤り（例：`a\times3` を `a3` と書く）は見つけられません。そのため「文字式の表し方」の問題は、必ず手動確認の対象にしています。
- **別解の妥当性**：全部正しい答案の途中式が `correctSolution` と違う場合は、手動確認の対象にしています。
- **解説・ヒントの内容、誤答の自然さ、難易度の妥当性**：文章や教育上の判断なので、人が確認します。
- **確率的な判定であること**：式の等価性は8点での一致で判定しています。中学で扱う次数の低い式では事実上確実ですが、厳密な証明ではありません。
- **対応していない記法・単元**：`\sqrt`、2次以上の方程式、連立方程式、2種類以上の文字を含む方程式は、現在は解析しません。そのような行は「判定不能（`?`）」となり、**自動では合格扱いにせず** MANUAL として表示します。
- **答えの形（約分・整理）**：最終行に × ÷ が残っている場合だけ MANUAL にしています。

### 手動レビューの記録

手動確認は、`review/manual-review.json` に問題ごとに記録しています（確認者、日付、確認項目、メモ、**問題内容の SHA-256 ハッシュ**）。
レビュー後に問題を変更するとハッシュが合わなくなり、「要再レビュー」と表示されます（`npm test` ではエラー）。

今回の30問は、Claude Code（AI）が全問を確認して記録しました。**実際に授業で使う前に、数学の先生による確認をおすすめします。**
先生が確認したら、`node tools/review-stamp.js --reviewer "先生の名前" ID ...` で記録できます（`--all` は、内容が変わっていない既存の記録をスキップします）。

### 第2段階の判断記録

| 判断が必要だった点 | 決めたこと | 理由 |
|---|---|---|
| 添削結果を別画面にするか | 問題画面の下（幅900px以上では右側）に結果パネルとして表示 | 答案と解説を見比べながら「どの行がなぜ誤りか」を確かめられるようにするため。iPad 横向きでは左右に並ぶ |
| 単元は複数選べるか | 1つだけ | 指示書の「以下から選択」に合わせた。`game.js` は単元を引数で受け取るので、将来の複数単元にも拡張しやすい |
| 「おまかせ」と個別の難易度の関係 | 「おまかせ」＝全難易度。おまかせの状態で ★ を押すと、その難易度だけになる | 「★★だけ練習したい」を1タップで選べるようにするため |
| 行番号の表示 | 1行目＝問題の式（選べない）、2行目以降を選択。画面の「○行目」は index＋1 | 指示書の表示例（1行目 3x+5=11 …）に合わせた |
| やめる確認 | ブラウザ標準の `confirm()` ではなく、画面内のダイアログ（`<dialog>`） | iPad でも見た目がそろい、自動テストもできるため |
| ブラウザの「戻る」 | プレイ中は確認ダイアログを出し、「つづける」なら進行状態をそのまま保つ | 意図しない画面遷移で進行状態が壊れないようにするため |
| 出題順の乱数 | 通常は `Math.random`。`?seed=` で固定できる | 不具合の再現と自動テストのため |
| データ不整合への対応 | 出題前に問題ごとに確認し、不整合な問題は出題から除外して設定画面に表示。採点時に見つかればエラー画面 | 「誤採点したまま進めない」（指示書5章） |

### 第1段階の仕様の判断記録

| # | 判断が必要だった点 | 決めたこと | 理由 |
|---|---|---|---|
| 1 | 単元ファイルの形式 | `{ schemaVersion, grade, unit, questions: [...] }` | 将来、項目を追加したときに版を区別できるようにするため |
| 2 | 単元ファイルの一覧 | `data/manifest.json` を追加 | ファイル名をプログラムに書かずに、単元を追加できるようにするため |
| 3 | 式の計算の2行目以降の書き方 | `=` で始める（`"=-5+8-6"`） | 参考PDFの書き方に合わせた。1行1式になる |
| 4 | `errorLine` に 0 を指定できるか | 指定できない（1 以上） | 1行目は問題を再掲した行で、添削の対象ではないため |
| 5 | 「式の値」の代入値 | 任意項目 `instruction`（表示用）と `substitution`（検証用）を追加 | 問題式だけでは代入する値がわからず、自動検証もできないため |
| 6 | 自動検証できない問題 | `verification: {mode:"manual"}` で明示。解析できない行も自動で MANUAL | 「自動的に合格扱いしない」を守るため |
| 7 | 手動確認の完了をどう示すか | 内容のハッシュ付きのレビュー記録 | 完了を確認でき、変更後の再レビューの必要がわかるようにするため |
| 8 | 説明文の中の数式 | `$...$` で書く | KaTeX で表示でき、構文も検証できるため |
| 9 | 解説の中で行番号を使うか | 使わず、式そのもので示す | `errorLine`（0始まり）と「〇行目」（1始まり）の取り違えを防ぐため |
| 10 | 「全部正しい」の割合 | 各単元3問・全体30% | 指示書の範囲内。別解の答案を入れるため上限の3問にした |
| 11 | 1次式の減法の分類 | 「分配法則など」 | かっこをはずす操作が中心になるため |
| 12 | 方程式 PDF の「比例式」 | 扱わない | 指示書の方程式のカテゴリにないため |
| 13 | 演算の優先順位（自動検証） | 暗黙のかけ算を `\times` `\div` より先に計算 | 日本の中学校の慣習（`x\div3y = \frac{x}{3y}`）に合わせた |
| 14 | KaTeX のバージョン | 0.16.47 に固定（CDN・npm とも） | 既知の脆弱性を修正した 0.16 系。`npm audit` に残る1件（GHSA-238p-pmpm-9mq7）は「すでにプロトタイプ汚染が起きている場合」に限られ、自分たちのデータだけを表示する本アプリへの影響は小さいと判断。0.19 系への更新は互換性の確認後に行う |
